# 消息渲染模块规范

> **模块路径**: `src/features/message/`
> **版本**: 1.0
> **状态**: 已实现

---

## 1. 模块概述

消息渲染模块负责将 AI 返回的多态消息内容转换为可视化的用户界面。每条消息由多个 **Part（内容片段）** 组成，系统根据 Part 的类型自动选择对应的渲染器，将文本、工具调用、推理过程、子任务、文件附件等内容以恰当的方式呈现给用户。

模块采用 **注册表模式** 管理工具渲染器，新增工具类型只需在注册表中添加配置即可，无需修改核心渲染逻辑。

### 1.1 设计目标

- 将多态消息内容（文本、工具调用、推理、子任务等）转换为结构化的视觉呈现
- 支持流式渐进渲染，内容到达即显示，无缓冲延迟
- 工具调用渲染器可扩展，通过注册表模式支持新工具类型
- 提供丰富的交互能力：折叠/展开、复制、全屏查看、权限确认
- 适配不同展示偏好：沉浸模式、描述型步骤、推理显示模式

### 1.2 模块边界

| 职责                           | 归属                                               |
| ------------------------------ | -------------------------------------------------- |
| 消息 Part 类型定义             | `types/message.ts`                                 |
| Markdown 渲染引擎              | `components/MarkdownRenderer.tsx`                  |
| 代码高亮组件                   | `components/CodeBlock.tsx`                         |
| 代码预览（虚拟滚动）           | `components/CodePreview.tsx`                       |
| 内容块容器（Diff/代码/加载态） | `components/ContentBlock.tsx`                      |
| 权限/问题内嵌交互              | `features/chat/InlinePermission`, `InlineQuestion` |
| **消息编排与 Part 分发渲染**   | **本模块**                                         |

## 2. 用户故事

### US-01 查看 AI 文本回复

作为用户，我希望看到 AI 的文本回复以格式化的 Markdown 呈现，包含标题、列表、表格、代码块等元素，以便清晰理解 AI 的回答。

### US-02 查看工具调用过程

作为用户，当 AI 执行命令、读写文件、搜索代码时，我希望看到每个工具调用的名称、输入参数、执行结果和耗时，以便了解 AI 的工作过程。

### US-03 查看 AI 的推理过程

作为用户，我希望能够查看 AI 的思考/推理过程，默认以简洁摘要形式展示，展开后可查看完整内容，以便理解 AI 的决策逻辑。

### US-04 跟踪子任务进度

作为用户，当 AI 启动子 Agent 任务时，我希望看到子任务的状态（运行中/已完成/出错），并能点击进入子会话查看完整对话，以便跟踪复杂任务的执行。

### US-05 查看文件附件

作为用户，当消息中包含文件、Agent 引用或系统上下文时，我希望以内联附件的形式查看，以便获取额外的上下文信息。

### US-06 处理工具调用中的权限请求

作为用户，当工具调用需要我授权时（如文件编辑），我希望在工具调用卡片内直接看到权限请求并完成操作，无需跳出当前上下文。

### US-07 查看文件变更差异

作为用户，当 AI 编辑文件时，我希望看到修改前后的 Diff 对比，包含新增/删除行数统计，以便审查代码变更。

### US-08 查看错误信息

作为用户，当消息或工具调用发生错误时，我希望看到清晰的错误提示，并可展开查看详细信息，以便诊断问题。

## 3. 功能需求

### FR-01 Part 类型分发

| 属性   | 描述              |
| ------ | ----------------- |
| 标识   | FR-01             |
| 名称   | Part 类型分发渲染 |
| 优先级 | P0                |

**描述**: 消息由多个 Part 组成，系统根据 Part 类型自动选择对应的渲染器：

- **连续工具合并**: 相邻的 ToolPart 被归组为工具组（ToolGroup），共享折叠状态和步骤摘要
- **基础设施过滤**: StepStart、Snapshot、Patch 等基础设施 Part 不直接渲染，参与内部状态管理
- **空内容跳过**: 空文本 Part 和空推理 Part 在非流式状态下自动跳过
- **流式布局动画**: 流式消息到达时使用平滑高度动画，避免布局跳动
- **入场生长动画**: 新消息从高度 0 平滑展开

**验收标准**:

- 每种 Part 类型都有对应的专用渲染器
- 连续工具调用归组渲染，共享折叠/展开状态
- 空 Part 不占用视觉空间
- 流式消息生长平滑，无跳动

### FR-02 工具调用渲染与注册表

| 属性   | 描述               |
| ------ | ------------------ |
| 标识   | FR-02              |
| 名称   | 工具调用渲染与扩展 |
| 优先级 | P0                 |

**描述**: 工具调用通过注册表模式匹配渲染器：

- **注册表匹配**: 按优先级顺序匹配工具名，第一个匹配的配置生效
- **专用渲染器**: Bash、Question、Task、Todo 等工具拥有专用渲染器
- **默认渲染器**: 未匹配专用渲染器的工具使用通用的 Input/Output 渲染
- **数据提取**: 每种工具可自定义数据提取器，从 ToolPart 的 state 中提取 input、output、diff、exitCode 等
- **图标系统**: 每种工具类型关联专属图标
- **三种布局变体**: 时间线布局（多工具）、紧凑布局（单工具）、描述型步骤（摘要模式）

**验收标准**:

- 新增工具类型只需在注册表中添加配置
- Bash 命令以终端风格渲染（$ 提示符、ANSI 颜色、闪烁光标）
- Todo 以清单形式展示，含完成进度
- Task 展示子 Agent 会话摘要，支持进入子会话
- Question 渲染已回答的选择题/多选题

### FR-03 Markdown 渲染

| 属性   | 描述              |
| ------ | ----------------- |
| 标识   | FR-03             |
| 名称   | Markdown 内容渲染 |
| 优先级 | P0                |

**描述**: 文本 Part 通过 Markdown 引擎渲染：

- **GFM 支持**: 表格、删除线、任务列表等 GitHub Flavored Markdown 语法
- **数学公式**: 支持 LaTeX 数学表达式渲染
- **代码块**: 自动检测语言，Shiki 语法高亮，带复制按钮
- **行内代码**: 带背景色和边框的样式
- **表格**: 带边框的表格，支持复制为 Markdown 格式
- **图片**: 懒加载，点击可打开原图
- **流式动画**: 流式内容到达时播放入场动画

**验收标准**:

- 代码块显示语言标签，支持一键复制
- 表格支持复制为 Markdown 文本
- 流式内容渲染无闪烁

### FR-04 代码块渲染

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-04          |
| 名称   | 语法高亮代码块 |
| 优先级 | P0             |

**描述**: 代码块使用 Shiki 进行语法高亮：

- **懒加载高亮**: 使用 IntersectionObserver，代码接近视口时才加载高亮
- **自动语言检测**: 无语言标签时自动检测（如识别树形结构）
- **两种变体**: 默认变体带标签栏和复制按钮，推理变体为极简样式
- **长行换行**: 支持按主题设置切换换行模式
- **移动端优化**: 触摸设备上复制按钮始终可见

**验收标准**:

- 远离视口的代码块不触发高亮计算
- 树形目录结构自动识别为 YAML 高亮
- 复制按钮 hover 时显示，触摸设备始终显示

### FR-05 推理/思考步骤展示

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-05        |
| 名称   | 推理过程展示 |
| 优先级 | P0           |

**描述**: 推理 Part 支持三种显示模式：

- **斜体模式**: 以斜体文本展示，简洁紧凑，流式思考时自动展开，完成后自动收起为摘要
- **Markdown 模式**: 以 Markdown 格式渲染推理内容，支持代码块、列表等
- **胶囊模式**: 带图标的可折叠卡片，展开后在滚动区域内展示完整内容

**验收标准**:

- 流式推理过程中自动展开显示
- 推理完成后自动收起为单行摘要
- 摘要文本溢出时显示省略号，点击可展开
- 显示思考耗时（ms/s 格式自适应）

### FR-06 子任务与步骤进度

| 属性   | 描述                   |
| ------ | ---------------------- |
| 标识   | FR-06                  |
| 名称   | 子任务与步骤进度可视化 |
| 优先级 | P0                     |

**描述**: 子任务和步骤进度的可视化展示：

- **子任务卡片**: 显示 Agent 名称、描述、运行状态（运行中/已完成/出错），支持点击进入子会话
- **步骤完成信息**: 展示 Token 用量、缓存命中、费用、消息耗时、回合总耗时
- **描述型步骤摘要**: 将多个工具调用按类别（执行、编辑、探索、网络等）汇总为一行文本
- **Diff 统计**: 工具组完成后显示总的新增/删除行数

**验收标准**:

- 子任务状态实时反映子会话状态
- 步骤完成信息可按主题设置选择性显示
- 描述型步骤摘要不超过 3 个类别，超出显示"更多操作"

### FR-07 错误状态展示

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-07        |
| 名称   | 错误状态渲染 |
| 优先级 | P0           |

**描述**: 错误信息以紧凑折叠式展示：

- **消息级错误**: 认证错误、输出超长、API 错误、中止错误等
- **工具级错误**: 单个工具调用失败，在工具卡片内以红色样式展示
- **重试信息**: 显示重试次数、可重试标识、错误详情
- **详情展开**: 点击可展开查看错误描述和原始响应体（JSON 格式化）

**验收标准**:

- 错误类型有明确的标题和描述
- JSON 格式的错误详情自动格式化
- 可重试错误显示重试标识

### FR-08 流式内容更新

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-08        |
| 名称   | 流式渐进渲染 |
| 优先级 | P0           |

**描述**: 消息内容通过 SSE 流式到达时的渲染行为：

- **即时渲染**: Part 到达即渲染，无缓冲延迟
- **平滑高度**: 使用 SmoothHeight 组件，内容增长时平滑动画
- **推理自动展开**: 流式推理内容到达时自动展开
- **工具自动展开**: 工具运行中时工具组保持展开
- **延迟卸载**: 折叠内容使用延迟渲染，展开后才挂载 DOM
- **Parts 补全**: 消息无 Parts 时自动触发补全请求

**验收标准**:

- 流式内容到达时布局平滑增长
- 用户查看历史消息时关闭流式布局动画，避免视口跳动
- 折叠状态切换无闪烁

## 4. Part 类型详解

消息中的 Part 是内容的基本单元，每种类型有独立的渲染行为。

### 4.1 Part 类型一览

| Part 类型          | 标识          | 渲染行为                         | 可见性                    |
| ------------------ | ------------- | -------------------------------- | ------------------------- |
| **TextPart**       | `text`        | Markdown 渲染文本内容            | 非空且非 synthetic 时可见 |
| **ReasoningPart**  | `reasoning`   | 推理/思考过程，可折叠            | 非空时可见                |
| **ToolPart**       | `tool`        | 工具调用，按注册表匹配渲染器     | 始终可见                  |
| **FilePart**       | `file`        | 文件附件，内联展示               | 始终可见                  |
| **AgentPart**      | `agent`       | Agent 引用，内联展示             | 始终可见                  |
| **SubtaskPart**    | `subtask`     | 子任务卡片，含状态和入口         | 始终可见                  |
| **StepFinishPart** | `step-finish` | 步骤完成信息（Token/费用/耗时）  | 按主题设置                |
| **RetryPart**      | `retry`       | 重试信息，含错误详情             | 始终可见                  |
| **CompactionPart** | `compaction`  | 上下文压缩标记，分隔线样式       | 始终可见                  |
| **PatchPart**      | `patch`       | 文件变更补丁，可展开查看文件列表 | 基础设施，不直接渲染      |
| **SnapshotPart**   | `snapshot`    | 状态快照                         | 基础设施，不直接渲染      |
| **StepStartPart**  | `step-start`  | 步骤开始标记                     | 基础设施，不直接渲染      |

### 4.2 渲染分组策略

Part 在渲染前经过分组处理，形成渲染项（RenderItem）：

1. **跳过基础设施**: StepStart、Snapshot、Patch 被过滤
2. **跳过空内容**: 空文本和空推理 Part 在非流式状态下被跳过
3. **工具归组**: 连续的 ToolPart 合并为工具组，附带关联的 StepFinishPart
4. **独立渲染**: 其余 Part 各自独立渲染

### 4.3 用户消息 Part 处理

用户消息中的 Part 处理方式不同：

- **文本 Part**: 合并为完整文本，使用可折叠文本组件展示（超长时默认折叠 8 行）
- **Synthetic Part**: 系统生成的上下文，折叠在"系统上下文"按钮下
- **FilePart / AgentPart**: 以内联附件形式展示
- **CompactionPart**: 显示上下文压缩分隔线

## 5. 工具渲染器注册表

### 5.1 注册表结构

工具注册表是一个有序配置列表，每个条目包含：

| 字段          | 类型         | 说明                                   |
| ------------- | ------------ | -------------------------------------- |
| `match`       | 函数         | 匹配函数，接收工具名返回是否匹配       |
| `icon`        | 组件         | 工具图标                               |
| `renderer`    | 组件（可选） | 专用渲染器，不提供时使用默认渲染       |
| `extractData` | 函数（可选） | 数据提取器，从 ToolPart 提取标准化数据 |

### 5.2 已注册工具

按匹配优先级排列：

| 工具模式  | 匹配关键词                             | 图标          | 专用渲染器       | 数据提取器       |
| --------- | -------------------------------------- | ------------- | ---------------- | ---------------- |
| Bash/终端 | bash, sh, cmd, terminal, shell         | TerminalIcon  | BashRenderer     | bashExtractData  |
| Todo      | todo                                   | ChecklistIcon | TodoRenderer     | 默认             |
| Task      | task（精确）                           | TaskIcon      | TaskRenderer     | 默认             |
| 读取文件  | read, cat                              | FileReadIcon  | 默认             | readExtractData  |
| 写入文件  | write, save                            | FileWriteIcon | 默认             | writeExtractData |
| 编辑文件  | edit, replace, patch                   | FileWriteIcon | 默认             | editExtractData  |
| 搜索      | search, find, grep, glob               | SearchIcon    | 默认             | 默认             |
| 网络      | web, fetch, http, browse, network, exa | GlobeIcon     | 默认             | 默认             |
| 思考      | think, reason, plan                    | BrainIcon     | 默认             | 默认             |
| 提问      | question, ask                          | QuestionIcon  | QuestionRenderer | 默认             |

### 5.3 标准化提取数据

所有工具的数据最终被提取为统一格式：

| 字段                    | 说明                                            |
| ----------------------- | ----------------------------------------------- |
| `input` / `inputLang`   | 输入参数及语言                                  |
| `output` / `outputLang` | 输出内容及语言                                  |
| `error`                 | 错误信息                                        |
| `diff`                  | 文件差异（before/after 或 unified diff 字符串） |
| `diffStats`             | 差异统计（新增/删除行数）                       |
| `files`                 | 多文件差异列表                                  |
| `filePath`              | 关联文件路径                                    |
| `exitCode`              | 退出码                                          |
| `diagnostics`           | LSP 诊断信息（错误/警告）                       |

### 5.4 专用渲染器说明

**BashRenderer**: 终端风格渲染

- `$` 提示符 + 命令（Shiki 高亮，点击复制）
- 输出支持 ANSI 颜色解析
- 运行中显示闪烁光标
- 完成后显示退出码

**TodoRenderer**: 清单风格渲染

- 显示任务列表，含状态图标（完成/进行中/待办/取消）
- 头部显示完成进度（已完成/总数）
- 高优先级任务标记感叹号
- 支持折叠/展开

**TaskRenderer**: 子 Agent 任务渲染

- 显示 Agent 类型徽章、任务描述、运行状态
- 运行中自动展开，显示子会话消息摘要
- 支持停止子会话、进入子会话
- 完成后显示输出结果

**QuestionRenderer**: 已回答问题渲染

- 展示问题文字和选项列表
- 已选选项高亮显示
- 支持自定义答案展示
- 多选模式显示复选框

**DefaultRenderer**: 通用渲染器

- Input 区块（非紧凑模式）
- Output 区块：优先显示错误，其次 loading 状态，最后显示结果
- 结果类型：多文件 Diff、单文件 Diff、普通文本输出
- Diagnostics 区块：LSP 错误/警告列表

## 6. 关键实体

### 6.1 MessageRenderer（消息渲染器）

消息渲染的入口组件，根据消息角色（user/assistant）分发到不同的视图。

**职责**:

- 用户消息: 渲染文本、附件、系统上下文、操作按钮（撤销/分叉/复制）
- 助手消息: 渲染 Part 列表、工具组、步骤完成信息、错误信息

### 6.2 AssistantMessageView（助手消息视图）

助手消息的主要渲染容器。

**职责**:

- 将 Part 列表分组为渲染项（单 Part 或工具组）
- 判断推理 Part 是否已结束（后续出现非基础设施 Part）
- 计算完整文本用于复制
- 管理流式布局动画
- 显示回合总耗时（可选）

### 6.3 ToolGroup（工具组）

连续工具调用的容器组件。

**职责**:

- 管理工具组的折叠/展开状态
- 显示步骤摘要（描述型模式）或步骤计数（默认模式）
- 沉浸模式下判断是否包含"可读工具"，决定完成后是否自动收起
- 汇总 Diff 统计
- 附带 StepFinishPart 显示步骤完成信息

### 6.4 ToolPartView（工具调用视图）

单个工具调用的渲染组件，支持三种布局变体。

**职责**:

- 根据布局变体选择渲染样式（时间线/紧凑/描述型）
- 管理工具卡片的折叠/展开
- 内嵌权限请求和提问请求
- 显示工具名称、标题、耗时、运行状态
- 根据工具类型选择渲染器（ToolBody）

### 6.5 ContentBlock（内容块）

通用内容展示容器，用于工具调用的 Input/Output 展示。

**职责**:

- 根据内容类型选择渲染器（代码预览 / Diff 查看器）
- 支持折叠/展开动画
- 支持加载状态（骨架屏）
- 支持全屏查看
- 响应式最大高度
- 显示 Diff 统计（新增/删除行数）和退出码

## 7. 验收场景

### 场景 1: 渲染 AI 文本回复

```
给定 助手消息包含一个非空的 TextPart
当 消息被渲染
那么 文本以 Markdown 格式展示
并且 代码块带有语法高亮和复制按钮
并且 表格带有边框和复制按钮
当 消息正在流式传输
那么 新内容到达时平滑增长
```

### 场景 2: 渲染 Bash 工具调用

```
给定 助手消息包含一个 bash 类型的 ToolPart
当 工具正在运行
那么 显示 $ 提示符和命令
并且 输出区域显示闪烁光标
当 工具执行完成
那么 显示命令输出（含 ANSI 颜色）
并且 显示退出码（绿色表示成功，黄色表示失败）
当 工具执行出错
那么 输出区域显示错误信息（红色）
```

### 场景 3: 渲染 Todo 工具调用

```
给定 助手消息包含一个 todo 类型的 ToolPart 且包含待办事项
当 消息被渲染
那么 显示清单列表，每项前有状态图标
并且 头部显示完成进度（如 "2/5 已完成"）
并且 高优先级任务标记感叹号
当 用户点击头部
那么 清单折叠/展开
```

### 场景 4: 渲染推理/思考过程

```
给定 助手消息包含一个 ReasoningPart
当 推理内容正在流式传输
那么 推理区域自动展开显示内容
并且 文本带有流光动画效果
当 推理完成
那么 自动收起为单行摘要
并且 摘要显示思考耗时
当 用户点击摘要
那么 展开显示完整推理内容
```

### 场景 5: 渲染工具组（多工具调用）

```
给定 助手消息包含连续的多个 ToolPart
当 消息被渲染
那么 工具被归组为一个工具组
并且 显示步骤计数（如 "3/3 步"）
并且 工具间有连接线（时间线布局）
当 用户点击步骤计数
那么 工具组折叠/展开
当 工具组包含可读工具（bash/write/edit 等）
那么 沉浸模式下完成后保持展开
当 工具组只包含不可读工具（read/search 等）
那么 沉浸模式下完成后自动收起
```

### 场景 6: 渲染子任务

```
给定 助手消息包含一个 SubtaskPart
当 消息被渲染
那么 显示子任务卡片，含 Agent 名称和描述
并且 状态指示点显示运行状态（绿色脉冲=运行中）
当 子会话已创建
那么 显示"进入"按钮
当 用户点击"进入"
那么 导航到子会话
当 用户点击卡片头部
那么 展开显示任务详情（prompt、模型、命令）
```

### 场景 7: 渲染消息级错误

```
给定 助手消息的 info 包含 error 字段
当 消息被渲染且无 Parts
那么 显示错误卡片
并且 错误类型有明确的标题（如"认证错误"、"API 错误"）
当 错误包含详细信息
那么 用户可点击展开查看
并且 JSON 格式的错误详情自动格式化
```

### 场景 8: 渲染文件编辑 Diff

```
给定 工具调用的 metadata 包含文件变更信息
当 消息被渲染
那么 显示 Diff 查看器
并且 头部显示文件名和 Diff 统计（+N -M）
当 用户点击全屏按钮
那么 在全屏查看器中展示 Diff
并且 支持 Split/Unified 两种视图模式
当 容器宽度 < 720px
那么 自动切换为 Unified 视图
```

### 场景 9: 描述型步骤摘要

```
给定 主题设置为描述型工具步骤模式
当 工具组被渲染
那么 头部显示分类摘要（如"执行了 2 个命令，编辑了 1 个文件"）
并且 摘要按类别分组，最多显示 3 个类别
当 类别超过 3 个
那么 显示"更多 N 个操作"
当 有工具正在运行
那么 运行中的类别以流光动画显示
当 有工具执行失败
那么 失败的类别以红色显示
```

## 9. 非功能需求

### 9.1 性能

- 代码高亮使用 IntersectionObserver 懒加载，距离视口 200px 时触发
- 折叠内容使用延迟渲染（DelayedRender），展开后才挂载 DOM
- 工具组状态切换时不重新挂载 ToolPartView，保持展开状态
- 流式布局动画使用 SmoothHeight 组件，避免布局跳动
- 用户查看历史消息时关闭流式布局动画，防止视口跳动

### 9.2 主题适配

- 推理显示模式：斜体 / Markdown / 胶囊（由主题控制）
- 工具卡片样式：标准 / 紧凑（由主题控制）
- 描述型工具步骤：开启/关闭（由主题控制）
- 沉浸模式：开启/关闭（由主题控制）
- 步骤完成信息显示项：Token/缓存/费用/耗时/回合耗时（由主题独立控制）
- 用户消息折叠：开启/关闭（由主题控制）

### 9.3 国际化

- 所有用户可见文本通过 i18n 键值管理
- 支持 `message` 和 `components` 两个命名空间

### 9.4 可访问性

- 折叠/展开按钮提供 `aria-expanded` 属性
- 推理摘要使用 `role="status"` 和 `aria-live="polite"`
- 所有交互元素支持键盘操作

## 10. 数据流概览

```
消息数据 (Message)
    ↓
MessageRenderer
    ├── 用户消息 → UserMessageView
    │       ├── 文本 → CollapsibleUserText
    │       ├── 附件 → FilePartView / AgentPartView
    │       ├── 系统上下文 → SyntheticTextPartView
    │       └── 压缩标记 → CompactionPartView
    │
    └── 助手消息 → AssistantMessageView
            ├── Part 分组 → groupPartsForRender()
            │       ├── 单 Part → 对应 PartView
            │       └── 工具组 → ToolGroup
            │
            ├── ToolGroup
            │       ├── 步骤摘要（描述型模式）
            │       └── ToolPartView × N
            │               ├── 工具图标 + 标题 + 耗时
            │               └── ToolBody
            │                       ├── TaskRenderer
            │                       ├── TodoRenderer
            │                       ├── 注册表匹配渲染器
            │                       └── DefaultRenderer
            │
            ├── ReasoningPartView
            ├── StepFinishPartView
            ├── SubtaskPartView
            └── MessageErrorView
```

工具数据提取流程：

```
ToolPart
    ↓
extractToolData(part)
    ├── 匹配注册表配置
    │       └── 调用自定义 extractData（如有）
    └── 否则调用 defaultExtractData
            ├── 提取 input（JSON 格式化）
            ├── 提取 output（字符串/JSON）
            ├── 提取 filePath
            ├── 提取 exitCode
            ├── 提取 diff/files（从 metadata）
            ├── 提取 diagnostics（从 metadata）
            └── 推断 outputLang（从 filePath）
    ↓
标准化 ExtractedToolData
    ↓
传递给渲染器
```
