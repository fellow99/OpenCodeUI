# 多窗格布局系统

> 模块编号：012-pane-layout
> 状态：已实现
> 最后更新：2026-04-12

---

## 1. 模块概述

### 1.1 目的

多窗格布局系统为用户提供灵活的 workspace 分割能力，支持将聊天区域拆分为多个独立窗格，每个窗格拥有自己的会话、控制器和交互上下文。通过递归二叉分割树模型，实现任意层级的水平与垂直分割，配合可拖拽调整大小的分隔条，构建高度可定制的多任务并行工作环境。

### 1.2 解决的问题

- **并行对话**：同时查看和参与多个独立对话，无需来回切换
- **灵活布局**：通过水平与垂直分割自由组合窗格排列方式
- **独立会话**：每个窗格追踪自己的会话状态，互不干扰
- **可调整大小**：拖拽分隔条精确控制每个窗格的显示比例
- **全屏聚焦**：临时将某个窗格放大至全屏，专注当前任务
- **窗格交换**：通过拖拽快速交换两个窗格的会话内容
- **布局持久化**：面板开关状态、尺寸等布局信息自动保存与恢复

### 1.3 范围

本模块涵盖：

- 递归二叉分割树的构建、查询、修改
- 窗格的创建、关闭、聚焦、全屏
- 可拖拽调整大小的分隔条
- 窗格间会话交换（拖拽交换）
- 每个窗格独立的会话控制器
- 右侧面板（文件浏览、变更查看、MCP、技能、Worktree）
- 底部面板（终端、文件浏览、变更查看等）
- 面板容器（统一标签页管理、拖拽排序、右键菜单）
- 布局状态的持久化与恢复
- 侧边栏展开/折叠状态管理

本模块不涵盖：

- 聊天界面的具体渲染逻辑（由聊天功能模块负责）
- 终端的 PTY 会话管理（由终端系统模块负责）
- 文件浏览与 Diff 查看的具体实现（由对应组件负责）

## 3. 功能需求

### FR-01：分割容器

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-01          |
| 名称   | 递归二叉分割树 |
| 优先级 | P0             |

**描述**：使用递归二叉树模型表示窗格布局，支持任意层级的水平与垂直分割。

**要求**：

- 树节点分为两种类型：叶子节点（PaneLeaf）和分割节点（PaneSplit）
- 分割节点包含两个子节点（first 和 second），以及分割方向（horizontal / vertical）和分割比例（ratio）
- 分割比例取值范围 0 到 1，表示 first 子节点占用的空间比例
- 渲染时递归遍历树，叶子节点渲染为窗格内容，分割节点渲染为带可拖拽分隔条的 CSS 网格容器
- 水平分割使用 grid-template-columns，垂直分割使用 grid-template-rows
- 分隔条具有额外的不可见命中区域，便于用户抓取
- 拖拽调整期间直接修改 DOM 样式（绕过框架渲染），使用 requestAnimationFrame 节流，松开鼠标后提交最终比例到状态存储

**验收标准**：

- 给定单个叶子节点，渲染为全屏窗格
- 给定一个水平分割节点，渲染为左右两个窗格，中间有可拖拽分隔条
- 给定嵌套分割（如水平分割的子节点又是垂直分割），正确渲染为三窗格布局
- 拖拽分隔条时窗格尺寸实时变化，松开后比例持久化到状态存储

### FR-02：窗格树结构

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-02          |
| 名称   | 窗格树数据结构 |
| 优先级 | P0             |

**描述**：定义窗格树的节点类型和操作接口。

**要求**：

- **PaneLeaf（叶子节点）**：包含唯一标识（id）和会话标识（sessionId），sessionId 为 null 时表示空窗格
- **PaneSplit（分割节点）**：包含唯一标识（id）、分割方向（direction）、分割比例（ratio）、第一子节点（first）、第二子节点（second）
- **PaneNode**：PaneLeaf 与 PaneSplit 的联合类型
- 支持按 id 查找叶子节点、遍历所有叶子节点、替换子树、移除叶子节点等操作
- 所有树操作返回新树（不可变更新），确保状态一致性

**验收标准**：

- 给定叶子节点，可以正确获取其 sessionId
- 给定分割节点，可以正确获取其 direction 和 ratio
- 移除叶子节点后，其兄弟节点自动提升为父节点
- 树操作不修改原树，返回新的树结构

### FR-03：可调整大小的分隔条

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-03          |
| 名称   | 拖拽调整分隔条 |
| 优先级 | P0             |

**描述**：分割节点之间的分隔条支持鼠标拖拽调整窗格比例。

**要求**：

- 分隔条为不可见的宽命中区域，覆盖网格间隙并向两侧延伸
- 水平分割的分隔条光标为 col-resize，垂直分割为 row-resize
- 拖拽期间：
  - 设置 body 的 cursor 和 userSelect 样式
  - 使用 requestAnimationFrame 节流 DOM 写入（每帧最多一次）
  - 直接修改容器的 grid-template 样式，绕过框架渲染
  - 触发 panel-resize-start 自定义事件
- 松开鼠标后：
  - 清除内联样式，将控制权交还框架
  - 计算最终比例并提交到状态存储（限制在 0.15 到 0.85 之间）
  - 触发 panel-resize-end 自定义事件
- 分隔条的 z-index 高于窗格内容，确保可交互

**验收标准**：

- 给定水平分割，拖拽分隔条左右移动时窗格宽度实时变化
- 给定垂直分割，拖拽分隔条上下移动时窗格高度实时变化
- 拖拽期间窗格内容不闪烁
- 松开鼠标后比例正确保存，刷新页面后恢复
- 拖拽期间其他组件（如终端）暂停响应 resize 事件

### FR-04：独立窗格状态

| 属性   | 描述               |
| ------ | ------------------ |
| 标识   | FR-04              |
| 名称   | 窗格独立会话控制器 |
| 优先级 | P0                 |

**描述**：每个窗格拥有独立的会话控制器，管理自己的会话状态和操作。

**要求**：

- 每个窗格通过 paneId 唯一标识
- 窗格控制器包含：paneId、sessionId、effectiveDirectory、contextLimit、isStreaming
- 窗格控制器提供操作接口：新建会话、归档会话、上一个/下一个会话、切换 Agent、复制最后回复、取消消息、打开模型选择器、切换全自动模式
- 控制器通过集中式存储注册和查询，支持按 paneId 获取对应控制器
- 窗格卸载时自动从存储中移除对应控制器
- 窗格切换会话时，控制器状态同步更新

**验收标准**：

- 给定两个窗格 A 和 B，各自拥有独立的 sessionId 和控制器
- 窗格 A 发送消息不影响窗格 B 的状态
- 关闭窗格后，其控制器从存储中移除
- 通过 paneId 可以正确获取对应的控制器实例

### FR-05：布局持久化

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-05          |
| 名称   | 布局状态持久化 |
| 优先级 | P1             |

**描述**：面板开关状态、尺寸等布局信息自动保存到本地存储，页面刷新后恢复。

**要求**：

- 侧边栏展开/折叠状态持久化
- 右侧面板开关状态和宽度持久化（范围 160px 到 1280px）
- 底部面板开关状态和高度持久化（范围 100px 到 500px）
- 面板标签页布局（类型、位置、排序、活动标签）持久化
- 终端标签页布局按工作目录分别持久化
- 持久化数据包含版本号，加载时进行校验和清理
- 存储异常时静默失败，不影响正常使用

**验收标准**：

- 给定打开右侧面板并调整宽度，刷新页面后面板保持打开且宽度一致
- 给定底部面板打开并调整高度，刷新页面后面板保持打开且高度一致
- 给定侧边栏折叠，刷新页面后侧边栏保持折叠
- 持久化数据损坏时，使用默认值恢复

| 名称   | 右侧面板 |

### FR-10：窗格全屏

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-10        |
| 名称   | 窗格全屏模式 |
| 优先级 | P1           |

**描述**：将指定窗格临时放大至全屏，隐藏其他窗格，退出后恢复原有布局。

**要求**：

- 进入全屏时记录当前窗格 id
- 全屏窗格使用绝对定位覆盖整个容器
- 非全屏窗格使用 content-visibility: hidden 隐藏，保持 DOM 和框架状态
- 退出全屏时恢复所有窗格的正常显示
- 分割操作时如果当前有全屏窗格，自动退出全屏
- 关闭全屏窗格时自动退出全屏模式

**验收标准**：

- 给定多窗格布局，点击全屏按钮后目标窗格占满整个区域
- 全屏期间其他窗格不可见但保持状态
- 退出全屏后所有窗格恢复原有布局和状态
- 全屏状态下执行分割操作，自动退出全屏

### FR-11：窗格交换

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-11        |
| 名称   | 窗格会话交换 |
| 优先级 | P1           |

**描述**：通过拖拽窗格头部，交换两个窗格的会话内容。

**要求**：

- 目标窗格头部接收拖拽时高亮显示
- 放下时交换两个窗格的 sessionId
- 同一窗格拖拽到自身不执行交换

**验收标准**：

- 给定窗格 A 有会话 X，窗格 B 有会话 Y
- 拖拽 A 的头部到 B 的头部并放下
- 窗格 A 显示会话 Y，窗格 B 显示会话 X
- 拖拽过程中目标窗格头部有视觉反馈

### FR-12：窗格导航

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-12        |
| 名称   | 窗格焦点导航 |
| 优先级 | P2           |

**描述**：支持在多个窗格之间切换焦点。

**要求**：

- 点击窗格内容自动聚焦该窗格
- 支持聚焦下一个窗格（循环）
- 支持聚焦上一个窗格（循环）
- 支持按索引聚焦（0-based）
- 聚焦状态影响窗格的视觉样式（如边框高亮）

**验收标准**：

- 给定三个窗格，当前聚焦窗格 1
- 执行聚焦下一个操作后，焦点移动到窗格 2
- 在最后一个窗格执行聚焦下一个操作后，焦点回到第一个窗格
- 聚焦的窗格有视觉高亮反馈

## 4. 关键实体

### 4.1 PaneNode（窗格节点）

窗格树的节点类型，为叶子节点和分割节点的联合类型。

```
PaneNode = PaneLeaf | PaneSplit
```

### 4.2 PaneLeaf（叶子节点）

树中的叶子节点，代表一个实际的窗格。

| 属性      | 类型           | 说明                           |
| --------- | -------------- | ------------------------------ |
| type      | 'leaf'         | 节点类型标识                   |
| id        | string         | 窗格唯一标识（格式：pane-N）   |
| sessionId | string \| null | 关联的会话 ID，null 表示空窗格 |

**行为**：

- 渲染为窗格内容（ChatPane）
- 可以关联或解除关联会话
- 可以被分割为两个子节点
- 可以被移除（关闭）

### 4.3 PaneSplit（分割节点）

树中的内部节点，代表一次分割操作。

| 属性      | 类型                       | 说明                                                 |
| --------- | -------------------------- | ---------------------------------------------------- |
| type      | 'split'                    | 节点类型标识                                         |
| id        | string                     | 分割节点唯一标识                                     |
| direction | 'horizontal' \| 'vertical' | 分割方向：horizontal 为左右分割，vertical 为上下分割 |
| ratio     | number                     | 分割比例（0-1），first 子节点占用的空间比例          |
| first     | PaneNode                   | 第一个子节点                                         |
| second    | PaneNode                   | 第二个子节点                                         |

**行为**：

- 渲染为 CSS 网格容器，中间有可拖拽分隔条
- 子节点可以是叶子节点或另一个分割节点（递归）
- ratio 可通过拖拽调整

## 5. 树结构

### 5.1 递归二叉分割树模型

窗格布局使用递归二叉树表示。树的每个内部节点代表一次分割操作，叶子节点代表实际的窗格。

```
                    ┌─────────────┐
                    │  PaneSplit  │  root
                    │  direction: │
                    │  horizontal │
                    │  ratio: 0.5 │
                    └──────┬──────┘
                           │
              ┌────────────┴────────────┐
              │                         │
       ┌──────▼──────┐           ┌──────▼──────┐
       │  PaneLeaf   │           │  PaneSplit  │
       │  id: pane-1 │           │  direction: │
       │  session: A │           │  vertical   │
       └─────────────┘           │  ratio: 0.6 │
                                 └──────┬──────┘
                                        │
                           ┌────────────┴────────────┐
                           │                         │
                    ┌──────▼──────┐           ┌──────▼──────┐
                    │  PaneLeaf   │           │  PaneLeaf   │
                    │  id: pane-2 │           │  id: pane-3 │
                    │  session: B │           │  session: C │
                    └─────────────┘           └─────────────┘
```

上图表示的布局：

- 根节点为水平分割，将空间分为左右两部分（各 50%）
- 左侧为单个窗格（pane-1，会话 A）
- 右侧为垂直分割，将空间分为上下两部分（上 60%，下 40%）
- 右上为窗格 pane-2（会话 B），右下为窗格 pane-3（会话 C）

### 5.2 树操作

#### 分割操作（splitPane）

给定一个叶子节点和分割方向，将该叶子替换为分割节点：

```
Before:                    After:
┌───────────┐              ┌─────┬─────┐
│  Leaf(A)  │     ──▶      │Leaf │Leaf │
│           │   split H    │ (A) │(new)│
└───────────┘              └─────┴─────┘
```

- 原有叶子节点保持其 sessionId
- 新创建的叶子节点 sessionId 为 null（空窗格）
- 分割比例初始为 0.5
- 焦点自动切换到新窗格

#### 关闭操作（closePane）

给定一个叶子节点，将其从树中移除：

```
Before:                    After:
┌─────┬─────┐              ┌───────────┐
│Leaf │Leaf │    close ──▶ │  Leaf(B)  │
│ (A) │ (B) │   Leaf(A)    └───────────┘
└─────┴─────┘
```

- 被关闭窗格的兄弟节点提升为父节点
- 如果树中只剩一个叶子节点，根节点直接变为叶子节点（退出分割模式）
- 如果关闭的是当前聚焦窗格，焦点自动切换到相邻窗格

#### 交换操作（swapPanes）

给定两个叶子节点的 id，交换它们的 sessionId：

```
Before:                    After:
┌─────┬─────┐              ┌─────┬─────┐
│Leaf │Leaf │    swap  ──▶ │Leaf │Leaf │
│ (A) │ (B) │              │ (B) │ (A) │
└─────┴─────┘              └─────┴─────┘
```

- 树结构不变，仅交换 sessionId
- 用于拖拽交换窗格内容

### 5.3 渲染策略

- 叶子节点：渲染为窗格内容组件
- 分割节点：渲染为 CSS 网格容器 + 可拖拽分隔条
- 全屏模式：全屏窗格使用绝对定位覆盖容器，非全屏窗格使用 content-visibility: hidden 隐藏
- 性能优化：窗格包裹器使用 contain: layout style 隔离内部重排，同时不使用 overflow: hidden 以保证子组件的 ring / box-shadow 边框可见

### 5.4 拖拽调整性能策略

拖拽调整分隔条时采用以下策略确保流畅体验：

1. 拖拽开始：设置 body 样式，注册全局 pointermove / pointerup 监听器
2. 拖拽过程中：
   - 计算鼠标位置相对于容器的比例
   - 使用 requestAnimationFrame 节流，每帧最多一次 DOM 写入
   - 直接修改容器的 grid-template-columns 或 grid-template-rows 样式
   - 绕过框架的状态更新和渲染流程
3. 拖拽结束：
   - 清除内联样式，将控制权交还框架
   - 计算最终比例并提交到状态存储
   - 触发 panel-resize-end 事件通知其他组件

## 6. 数据流

### 6.1 窗格分割流程

```
用户点击分割按钮
    ↓
paneLayoutStore.splitPane(paneId, direction)
    ↓
查找目标叶子节点
    ↓
创建新叶子节点 + 分割节点
    ↓
替换原叶子为分割节点（不可变更新）
    ↓
更新聚焦到新窗格
    ↓
刷新快照，通知订阅者
    ↓
框架重新渲染分割树
```

### 6.2 分隔条拖拽流程

```
用户按下分隔条
    ↓
设置 body cursor / userSelect
    ↓
注册全局 pointermove / pointerup
    ↓
pointermove → 计算比例 → rAF 节流 → 直接修改 grid-template
    ↓
触发 panel-resize-start 事件
    ↓
pointerup → 清除内联样式 → 计算最终比例 → 提交到 store
    ↓
触发 panel-resize-end 事件
    ↓
框架根据新比例重新渲染
```

### 6.3 窗格会话切换流程

```
用户在窗格中选择会话
    ↓
paneLayoutStore.setPaneSession(paneId, sessionId)
    ↓
查找叶子节点，更新 sessionId
    ↓
刷新快照，通知订阅者
    ↓
对应窗格重新渲染，加载新会话
    ↓
paneControllerStore 更新控制器状态
```

### 6.4 面板标签页管理流程

```
用户点击添加标签按钮
    ↓
layoutStore.addTab({ type, position })
    ↓
创建新 PanelTab，添加到 panelTabs
    ↓
设置对应位置的 activeTabId
    ↓
自动打开对应面板
    ↓
持久化到 localStorage
    ↓
通知订阅者，框架重新渲染
```

### 6.5 终端会话恢复流程

```
页面加载 / 目录切换
    ↓
listPtySessions() 查询已有 PTY 会话
    ↓
layoutStore.syncTerminalSessions(directory, sessions)
    ↓
读取该目录的持久化布局信息
    ↓
合并已有终端标签和非终端标签
    ↓
更新 panelTabs 和 activeTabId
    ↓
通知订阅者，终端组件自动连接 WebSocket
```

## 10. 架构决策记录

### ADR-001：为什么使用递归二叉树而非网格布局

**决策**：窗格布局采用递归二叉分割树模型，而非 CSS Grid 的多行列网格。

**理由**：

- 二叉树天然支持递归分割，每次分割只影响一个区域
- 树结构易于序列化和持久化
- 添加/删除窗格时只需局部修改树结构
- 分割比例通过 ratio 字段精确控制，不受网格行列限制
- 与 VS Code 等成熟编辑器的布局模型一致

### ADR-002：为什么拖拽调整期间绕过框架渲染

**决策**：分隔条拖拽过程中直接修改 DOM 的 grid-template 样式，不通过框架的状态更新机制。

**理由**：

- 框架的状态更新和渲染流程在高频拖拽时会产生性能瓶颈
- 直接修改 DOM 避免了每帧的虚拟 DOM diff 和组件重渲染
- 使用 requestAnimationFrame 节流确保每帧最多一次 DOM 写入
- 松开鼠标后清除内联样式，将控制权交还框架，确保状态一致性
- 窗格包裹器使用 contain: layout style 隔离内部重排

### ADR-003：为什么全屏模式使用 content-visibility 而非卸载组件

**决策**：全屏模式下非全屏窗格使用 content-visibility: hidden 隐藏，而非从 DOM 中移除。

**理由**：

- 卸载/重新挂载组件会导致状态丢失和重新初始化开销
- content-visibility: hidden 保持 DOM 和框架状态，仅跳过渲染
- 退出全屏时即时恢复，无需重新加载会话数据
- 全屏窗格使用绝对定位覆盖容器，确保正确的层叠关系

### ADR-004：为什么面板标签页统一为 PanelTab 类型

**决策**：右侧面板和底部面板的标签页统一使用 PanelTab 类型，通过 type 和 position 字段区分。

**理由**：

- 避免为每种面板类型维护独立的状态管理
- 标签页可以在两个面板之间自由移动
- 统一的添加、移除、排序、移动操作接口
- 持久化时只需存储一份标签页布局数据
- 终端标签按目录分组持久化，非终端标签全局持久化

### ADR-005：为什么窗格交换仅交换 sessionId 而非树节点

**决策**：拖拽交换窗格时，仅交换两个叶子节点的 sessionId，不改变树结构。

**理由**：

- 树结构代表布局，sessionId 代表内容，两者应解耦
- 交换 sessionId 比交换树节点更简单，不需要处理子树替换
- 布局保持不变，用户感知为"内容交换"而非"布局变化"
- 避免了复杂的树操作可能引入的 bug

## 11. 风险与缓解

| 风险                                 | 影响                                  | 缓解措施                                                 |
| ------------------------------------ | ------------------------------------- | -------------------------------------------------------- |
| 深层嵌套分割导致渲染性能下降         | 树深度过大时递归渲染开销增加          | 实际使用中分割层级有限，CSS contain 属性隔离重排         |
| 拖拽调整期间与其他 resize 监听器冲突 | 终端等组件在拖拽过程中频繁调整大小    | 通过 panel-resize-start/end 自定义事件通知，拖拽期间暂停 |
| 窗格控制器内存泄漏                   | 窗格关闭后控制器未清理，占用内存      | 窗格组件卸载时自动调用 removeController                  |
| 持久化数据损坏导致布局异常           | localStorage 数据被篡改或版本不兼容   | 加载时进行严格校验，损坏时使用默认值恢复                 |
| 全屏模式下分割操作导致状态不一致     | 全屏时执行分割可能丢失全屏状态        | 分割操作时自动退出全屏模式                               |
| 多窗格同时流式输出导致性能问题       | 多个窗格同时接收 SSE 消息，渲染压力大 | 每个窗格独立管理流式状态，RAF 批量合并通知               |
| 并发目录切换导致终端标签状态混乱     | 快速切换工作目录时终端会话同步不正确  | requestId 机制确保仅最后一次请求生效                     |
| 分隔条命中区域过小导致难以抓取       | 用户难以精确点击到分隔条              | 分隔条具有额外的不可见命中区域（HIT_EXTEND = 4px 每侧）  |
