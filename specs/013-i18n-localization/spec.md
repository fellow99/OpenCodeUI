# 国际化（i18n）模块规格

## 1. 模块概述

本模块为 OpenCodeUI 提供多语言支持能力。翻译文件采用基于命名空间（Namespace）的 JSON 格式，按功能领域组织，支持运行时语言切换、浏览器语言自动检测、变量插值等核心能力。

**当前支持语言：**

| 语言代码 | 语言名称 | 状态   |
| -------- | -------- | ------ |
| `zh-CN`  | 简体中文 | 已实现 |
| `en`     | 英语     | 已实现 |

**加载策略：** 构建时通过 Vite 的 glob 导入机制，在应用初始化阶段一次性加载所有翻译文件（Eager Loading）。

## 2. 用户故事

| 编号  | 用户故事                                                                 | 优先级 |
| ----- | ------------------------------------------------------------------------ | ------ |
| US-01 | 作为中文用户，我希望应用界面以简体中文显示，以便顺畅阅读和操作           | P0     |
| US-02 | 作为英文用户，我希望应用界面以英语显示                                   | P0     |
| US-03 | 作为用户，我希望应用能自动检测浏览器语言设置并匹配对应语言，减少手动配置 | P1     |
| US-04 | 作为多语言用户，我希望能在不刷新页面的情况下切换语言                     | P1     |
| US-05 | 作为用户，我希望我选择的语言偏好能被记住，下次打开应用时自动生效         | P1     |

## 3. 功能需求

### FR-01：多语言支持

系统当前支持简体中文（`zh-CN`）和英语（`en`）两种语言。新增语言时，只需在 `src/locales/` 下创建对应语言代码的目录，并放置与现有语言相同结构的命名空间 JSON 文件。

### FR-02：基于命名空间的翻译组织

翻译文件按功能领域拆分为独立的命名空间（Namespace），每个命名空间对应一个 JSON 文件。这种组织方式使得翻译文件可按模块加载和维护，避免单一文件过大。

### FR-03：语言自动检测

应用启动时按以下优先级顺序检测用户语言：

1. **localStorage** — 读取用户上次手动选择的语言偏好（存储键为 `i18nextLng`）
2. **浏览器语言设置** — 读取 `navigator.language`

检测结果将缓存至 localStorage，确保用户偏好持久化。

### FR-04：运行时语言切换

用户可在不刷新页面的情况下切换语言。切换后，所有使用翻译的组件自动更新为对应语言的文本。

### FR-05：回退链（Fallback Chain）

当某个翻译键在当前语言中不存在时，系统自动回退到默认语言（`en`）查找对应键值。这确保了即使新增翻译键尚未完成所有语言的翻译，界面也不会出现键名裸露。

### FR-06：变量插值

翻译字符串支持通过 `{{变量名}}` 语法进行变量替换。例如：

```
"remaining": "剩余 {{count}} 个"
```

运行时将 `{{count}}` 替换为实际数值。

### FR-07：富文本插值

部分翻译字符串支持 React 组件级别的插值，使用 `<索引>内容</索引>` 语法。例如：

```
"pressEscAgain": "再按一次 <1>Esc</1> 停止"
```

其中 `<1>Esc</1>` 在渲染时会被替换为对应的 React 组件（如高亮样式的按键标签）。

## 4. 翻译命名空间

每个语言目录下包含以下 6 个命名空间文件：

| 命名空间     | 文件名            | 职责范围                                                     |
| ------------ | ----------------- | ------------------------------------------------------------ |
| `common`     | `common.json`     | 全局通用文案：按钮文本、状态提示、操作标签等                 |
| `chat`       | `chat.json`       | 聊天界面：侧边栏、输入框、模型选择器、会话状态、分享对话框等 |
| `commands`   | `commands.json`   | 斜杠命令：命令名称、描述、参数提示等                         |
| `components` | `components.json` | 可复用组件：文件浏览器、终端、Diff 视图等通用组件文案        |
| `message`    | `message.json`    | 消息渲染：AI 回复、工具调用、错误消息等展示文案              |
| `settings`   | `settings.json`   | 设置面板：配置项标签、说明文字、表单提示等                   |

**命名空间内的键采用嵌套对象结构**，通过点号路径访问。例如 `chat.header.newChat` 对应 `chat.json` 中 `header` 对象下的 `newChat` 键。

## 5. 关键实体

### Locale（语言区域）

表示一种支持的语言。由 BCP 47 语言代码标识（如 `zh-CN`、`en`）。

| 属性    | 类型     | 说明                    |
| ------- | -------- | ----------------------- |
| `code`  | `string` | 语言代码，如 `zh-CN`    |
| `label` | `string` | 显示名称，如 "简体中文" |

### Namespace（命名空间）

翻译文件的逻辑分组，对应一个 JSON 文件。

| 属性   | 类型                      | 说明                              |
| ------ | ------------------------- | --------------------------------- |
| `name` | `string`                  | 命名空间标识，如 `common`、`chat` |
| `keys` | `Record<string, unknown>` | 该命名空间下的所有翻译键值对      |

### TranslationKey（翻译键）

用于定位具体翻译字符串的路径标识。

| 属性                | 类型       | 说明                                       |
| ------------------- | ---------- | ------------------------------------------ |
| `namespace`         | `string`   | 所属命名空间                               |
| `keyPath`           | `string`   | 点号分隔的键路径，如 `chat.header.newChat` |
| `interpolationVars` | `string[]` | 插值变量名列表，如 `["count"]`             |

## 6. 配置参数

| 参数                           | 值                              | 说明                                         |
| ------------------------------ | ------------------------------- | -------------------------------------------- |
| `fallbackLng`                  | `en`                            | 默认回退语言                                 |
| `defaultNS`                    | `common`                        | 默认命名空间                                 |
| `ns`                           | 动态推导                        | 从 `en` 语言目录中读取所有可用的命名空间名称 |
| `detection.order`              | `['localStorage', 'navigator']` | 语言检测优先级                               |
| `detection.caches`             | `['localStorage']`              | 缓存策略                                     |
| `detection.lookupLocalStorage` | `i18nextLng`                    | localStorage 存储键名                        |
| `interpolation.escapeValue`    | `false`                         | 关闭 HTML 转义（由 React 负责）              |

## 7. 验收场景

### 场景 1：首次访问 — 自动检测浏览器语言

**前置条件：** 用户首次访问应用，localStorage 中无语言偏好记录。

**步骤：**

1. 用户打开应用
2. 系统读取浏览器语言设置（`navigator.language`）

**预期结果：**

- 浏览器语言为 `zh-CN` 或 `zh-*` 时，界面显示简体中文
- 浏览器语言为其他值时，界面显示英语（回退到 `fallbackLng`）

### 场景 2：手动切换语言

**前置条件：** 应用已加载，当前语言为英语。

**步骤：**

1. 用户在设置面板中将语言切换为"简体中文"
2. 观察界面变化

**预期结果：**

- 所有界面文本立即切换为简体中文，无需刷新页面
- 语言偏好写入 localStorage，键为 `i18nextLng`，值为 `zh-CN`

### 场景 3：语言偏好持久化

**前置条件：** 用户上次将语言设置为简体中文。

**步骤：**

1. 用户关闭浏览器后重新打开应用

**预期结果：**

- 应用自动读取 localStorage 中的语言偏好
- 界面以简体中文显示

### 场景 4：翻译键缺失时的回退

**前置条件：** `zh-CN` 的某个命名空间中缺少某个翻译键，但 `en` 中存在该键。

**步骤：**

1. 界面渲染需要该翻译键的组件

**预期结果：**

- 显示英语版本的翻译文本
- 不显示原始键名或空白

### 场景 5：变量插值正确渲染

**前置条件：** 翻译字符串包含 `{{count}}` 等插值占位符。

**步骤：**

1. 组件渲染该翻译键并传入变量值（如 `count: 5`）

**预期结果：**

- 显示 "剩余 5 个"（中文）或 "5 remaining"（英文）
- 占位符被正确替换为实际值

### 场景 6：新增语言扩展

**前置条件：** 需要新增日语（`ja`）支持。

**步骤：**

1. 在 `src/locales/` 下创建 `ja/` 目录
2. 复制现有命名空间文件结构（`common.json`、`chat.json` 等 6 个文件）
3. 将翻译内容替换为日语

**预期结果：**

- 应用启动时自动识别新语言目录
- 用户可在语言选择器中看到"日本語"选项
- 切换后界面以日语显示

## 8. 目录结构

```
src/locales/
├── en/                    # 英语（默认回退语言）
│   ├── common.json        # 全局通用文案
│   ├── chat.json          # 聊天界面
│   ├── commands.json      # 斜杠命令
│   ├── components.json    # 可复用组件
│   ├── message.json       # 消息渲染
│   └── settings.json      # 设置面板
└── zh-CN/                 # 简体中文
    ├── common.json
    ├── chat.json
    ├── commands.json
    ├── components.json
    ├── message.json
    └── settings.json
```

## 9. 约束与限制

- 所有翻译文件必须为合法的 JSON 格式
- 新增语言时，必须包含与 `en` 相同的全部命名空间文件
- 翻译键的命名采用 camelCase 风格
- 嵌套层级不宜过深，建议不超过 3 层
- 插值变量名使用英文字母和下划线，避免特殊字符
