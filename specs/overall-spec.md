# OpenCodeUI 总体规格说明书

> 版本：1.0
> 状态：草案
> 本文档描述 OpenCodeUI 系统做什么（WHAT）和为什么做（WHY），不涉及具体实现技术。

---

## 1. 产品愿景

OpenCodeUI 是一个面向开发者的 AI 编程助手前端界面，为 [OpenCode](https://github.com/anomalyco/opencode) 后端提供完整的用户交互层。

**为什么存在：** 开发者需要一个高效、直观的界面来与 AI 编程助手对话。OpenCodeUI 以聊天为核心，将文件操作、终端执行、代码修改、权限审批等复杂能力整合到一个统一的界面中，让开发者能够像与同事协作一样自然地与 AI 共同编写代码。

**目标用户：** 软件开发者、DevOps 工程师、技术团队。

**核心价值：**

- 以对话式界面降低 AI 编程助手的使用门槛
- 实时可见 AI 的思考过程和工具调用结果
- 对 AI 的文件修改提供精确的 diff 审查和权限控制
- 支持多项目、多会话并行工作
- 可在浏览器、桌面应用、容器化部署等多种环境中运行

## 3. 功能需求

### FR-01: 实时双向通信

系统必须支持与 AI 后端的实时双向通信：

- 用户发送消息后，系统将其转发至后端
- 系统接收并渲染后端返回的流式响应（SSE 协议）
- 系统能够处理连接中断并自动重连
- 系统支持取消正在进行的响应

### FR-02: 会话生命周期管理

系统必须提供完整的会话管理能力：

- **创建**：用户可以发起新的对话会话
- **恢复**：用户可以打开并继续历史会话
- **分叉**：用户可以从任意消息点创建会话分支
- **撤销**：用户可以撤回已发送的用户消息
- **重命名**：用户可以修改会话标题
- **删除**：用户可以删除单个或多个会话
- **归档**：用户可以归档不再活跃的会话
- **分享**：用户可以生成会话的公开分享链接
- **导航**：用户可以在会话列表中快速前进/后退

### FR-03: 消息渲染

系统必须能够渲染多种类型的消息内容：

- **Markdown 文本**：支持 GFM（GitHub Flavored Markdown）
- **代码块**：带语法高亮、行号、复制按钮
- **工具调用结果**：展示 AI 调用的工具名称、参数、执行状态和结果
- **推理过程**：可折叠展示 AI 的思考过程
- **文件操作**：展示文件读取、编辑、写入的操作详情
- **子任务**：展示 AI 分解的子任务及其状态
- **步骤信息**：展示每个执行步骤的耗时和资源消耗
- **错误信息**：友好展示各类错误（认证失败、API 错误等）
- **压缩信息**：展示上下文压缩事件

### FR-04: 文件与符号引用系统（@ 提及）

系统必须提供 @ 提及功能：

- 用户在输入框中输入 @ 时触发自动补全菜单
- 支持三种提及类型：文件、文件夹、代码符号
- 菜单支持模糊搜索和键盘导航
- 提及项在消息中以可视化标签形式展示
- 提及信息在发送时转换为结构化格式传递给后端

### FR-05: 命令系统（斜杠命令）

系统必须提供斜杠命令功能：

- 用户在输入框中输入 / 时触发命令菜单
- 命令菜单展示可用命令列表及其描述
- 支持键盘导航和选择
- 命令执行后自动关闭菜单并继续输入

### FR-06: 集成终端

系统必须提供集成终端功能：

- 支持创建和管理多个终端会话
- 终端支持完整的 PTY（伪终端）交互
- 支持标签页切换、创建和关闭
- 终端可在底部面板或右侧面板中展示
- 终端会话与项目目录关联
- 支持终端会话的持久化和恢复

### FR-07: 文件 Diff 可视化

系统必须提供文件差异查看能力：

- **单文件 Diff**：并排或内联展示单个文件的修改前后
- **多文件 Diff**：在一个视图中汇总展示多个文件的变更
- **权限请求中的 Diff**：在权限审批界面中嵌入 diff 展示
- 支持新增行和删除行的高亮标识
- 支持 diff 内容的复制

### FR-08: 主题定制

系统必须提供灵活的外观定制能力：

- 提供多套内置主题预设（至少三套）
- 每套主题包含明暗两套配色
- 支持明暗模式切换：手动明亮、手动黑暗、跟随系统
- 支持通过自定义 CSS 变量覆盖主题颜色
- 主题选择持久化保存

### FR-09: 多窗格布局

系统必须支持多窗格分屏布局：

- 支持将聊天区域水平或垂直分割为多个窗格
- 每个窗格独立加载和显示一个会话
- 支持通过拖拽调整窗格大小
- 支持窗格的全屏/还原切换
- 支持窗格的关闭和新建
- 窗格布局状态持久化保存

### FR-10: 国际化

系统必须支持多语言：

- 支持中文（简体）和英文两种界面语言
- 所有用户可见文本均支持翻译
- 语言设置持久化保存
- 覆盖范围包括：界面标签、命令描述、设置项、错误提示、通知消息

### FR-11: 权限与问答工作流

系统必须处理 AI 后端的权限请求和问答请求：

- **权限请求**：
  - 在聊天流中内联展示权限请求
  - 展示请求的工具名称、描述和涉及的文件
  - 对于文件编辑类请求，展示 diff 预览
  - 提供"允许"、"拒绝"、"本次会话始终允许"选项
  - 支持权限请求队列（多个请求依次处理）
  - 支持子 Agent 发起的权限请求展示来源信息

- **问答请求**：
  - 在聊天流中内联展示问答请求
  - 展示问题描述和可选答案（支持多选）
  - 支持自定义输入答案
  - 提供"提交"和"拒绝回答"操作

### FR-12: MCP 服务器管理

系统必须提供 MCP（Model Context Protocol）服务器管理能力：

- 展示所有已配置 MCP 服务器的列表和连接状态
- 支持连接和断开 MCP 服务器
- 支持 MCP 服务器的 OAuth 认证流程
- 支持添加新的 MCP 服务器配置
- 支持刷新服务器状态

### FR-13: 桌面应用打包

系统必须支持桌面应用分发：

- 支持 macOS、Linux、Windows 三个平台
- 桌面应用具备原生窗口管理能力
- 桌面应用包含独立的运行时环境

### FR-14: 容器化部署与网关路由

系统必须支持容器化部署：

- 提供完整的多服务容器编排（前端、后端、网关）
- 网关统一对外路由，按路径规则分发请求
- 支持动态端口路由：容器内开发服务自动发现并生成外部可访问链接
- 支持纯前端独立部署模式（仅前端容器连接外部后端）
- 支持反向代理配置（Nginx、Caddy）
- 数据持久化卷管理

### FR-15: 键盘快捷键定制

系统必须提供可配置的键盘快捷键系统：

- 覆盖所有核心操作：会话管理、窗格操作、终端、设置等
- 支持查看当前快捷键绑定
- 支持自定义修改快捷键绑定
- 快捷键设置持久化保存
- 在命令面板中展示命令对应的快捷键

### FR-16: 通知系统

系统必须提供通知能力：

- **浏览器通知**：AI 回复完成时推送系统级通知
- **通知声音**：可配置的提示音
- **未读标记**：在侧边栏会话列表中标记有未读通知的会话
- 通知设置（开关、声音）可配置

## 4. 关键实体

以下是系统中的核心抽象实体，不依赖具体实现技术：

| 实体                   | 描述                                                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **会话（Session）**    | 一次独立的对话上下文，包含一组按时间排序的消息。会话可以创建、恢复、分叉、删除、分享和归档。                     |
| **消息（Message）**    | 会话中的单条通信单元，分为用户消息和助手消息。每条消息包含元信息（角色、时间、模型引用、Token 用量）和内容片段。 |
| **片段（Part）**       | 消息内容的组成单元，可以是文本、推理、工具调用、文件操作、代理调用、步骤信息、子任务、重试、压缩等类型。         |
| **权限（Permission）** | AI 后端发起的操作审批请求，包含工具类型、描述、涉及文件及 diff 信息。用户可批准、拒绝或设置会话级自动批准。      |
| **问答（Question）**   | AI 后端发起的信息征询请求，包含问题描述和一组可选答案。用户可选择预设答案或输入自定义回答。                      |
| **待办（Todo）**       | AI 在执行任务过程中维护的任务清单，用于跟踪进度。                                                                |
| **项目（Project）**    | 一个工作区目录路径，代表一个独立的开发项目。系统可同时管理多个项目。                                             |
| **提供商（Provider）** | AI 模型服务的提供方，如 Anthropic、OpenAI 等。                                                                   |
| **模型（Model）**      | 具体的 AI 模型标识，归属于某个提供商，可有不同的变体配置。                                                       |
| **PTY**                | 伪终端会话，提供完整的终端交互能力，支持创建、连接、断开和恢复。                                                 |
| **文件（File）**       | 项目目录中的文件实体，可被浏览、提及、附加到消息中。                                                             |
| **差异（Diff）**       | 文件修改前后的对比信息，支持统一 diff 格式和结构化的逐行对比。                                                   |
| **MCP 服务器**         | 遵循 Model Context Protocol 的外部服务，为 AI 提供扩展能力。包含名称、连接状态和认证信息。                       |

## 5. 验收场景

### 5.1 发起对话并获取流式回复

```
场景：用户发送消息并接收 AI 的流式回复
前置条件：系统已连接到可用的 AI 后端

1. 用户在输入框中输入文本
2. 用户按下发送键
3. 系统显示用户消息到聊天区域
4. 系统开始接收并实时渲染 AI 的流式回复
5. 用户可以看到回复内容逐字出现
6. AI 回复完成后，系统显示完整的消息
7. 系统触发完成通知（如果通知已启用）
```

### 5.2 文件修改权限审批

```
场景：AI 尝试修改文件时用户进行审批
前置条件：AI 在执行任务过程中需要修改文件

1. AI 向后端发起文件编辑请求
2. 系统在聊天流中内联展示权限请求
3. 权限请求展示文件名和修改 diff 预览
4. 用户查看 diff 内容
5. 用户点击"允许"按钮
6. 系统向 AI 后端发送批准回复
7. 权限请求标记为已批准状态
8. AI 继续执行后续操作
```

### 5.3 使用 @ 提及文件

```
场景：用户在消息中提及特定文件
前置条件：用户已打开一个项目目录

1. 用户在输入框中输入 @ 字符
2. 系统展示文件/符号自动补全菜单
3. 用户输入文件名进行过滤
4. 用户从菜单中选择目标文件
5. 系统在输入框中插入文件提及标签
6. 用户继续输入其他内容并发送消息
7. 消息中的提及以可视化标签形式展示
```

### 5.4 创建和管理多窗格

```
场景：用户将聊天区域分割为两个窗格
前置条件：用户正在查看一个会话

1. 用户触发"向右分割"操作
2. 系统将当前区域水平分割为两个窗格
3. 左侧窗格保持当前会话
4. 右侧窗格显示新会话或空状态
5. 用户可以通过拖拽调整两个窗格的宽度比例
6. 用户可以点击任一窗格切换焦点
7. 用户可以在每个窗格中独立进行对话
```

### 5.5 切换主题

```
场景：用户从默认主题切换到另一套预设主题
前置条件：系统已安装多套主题

1. 用户打开设置面板
2. 用户导航到"外观"标签
3. 用户从主题列表中选择新主题
4. 系统立即应用新主题的配色方案
5. 界面所有元素的颜色更新为新主题定义的值
6. 主题选择被持久化保存
7. 下次打开系统时，新主题仍然生效
```

### 5.6 使用集成终端

```
场景：用户在界面内打开终端并执行命令
前置条件：系统已连接到 AI 后端

1. 用户触发"打开终端"操作
2. 系统在底部面板中创建新的终端标签页
3. 终端建立 PTY 连接
4. 用户在终端中输入命令
5. 终端展示命令输出（包括颜色和高亮）
6. 用户可以创建额外的终端标签页
7. 用户可以在标签页之间切换
```

### 5.7 分享会话

```
场景：用户生成并分享当前会话的公开链接
前置条件：用户正在查看一个会话

1. 用户触发"分享"操作
2. 系统向后端请求生成分享链接
3. 系统展示生成的 URL
4. 用户点击"复制链接"按钮
5. 链接被复制到剪贴板
6. 用户可以将链接发送给他人
7. 接收者可以通过链接查看会话内容
```

### 5.8 会话分叉

```
场景：用户从某条消息处分叉会话以探索不同思路
前置条件：用户正在查看一个包含多条消息的会话

1. 用户定位到想要分叉的消息
2. 用户触发"从此处分叉"操作
3. 系统创建新的会话，包含从开始到该消息的所有历史
4. 系统自动切换到新会话
5. 用户可以在新会话中发送不同的消息
6. 原始会话保持不变
```

## 6. 非功能需求

### 6.1 性能

- **流式响应延迟**：从后端推送数据到界面渲染的延迟不超过 100ms
- **会话列表加载**：初始加载和滚动加载更多会话时不阻塞用户交互
- **消息渲染**：长消息（含大量代码块和工具调用）的渲染不造成界面卡顿
- **终端响应**：终端输入到输出显示的延迟不超过 50ms
- **内存管理**：长时间使用后不应出现明显的内存增长

### 6.2 可访问性

- 所有交互元素可通过键盘访问
- 按钮和链接具有有意义的无障碍标签
- 颜色对比度符合 WCAG 2.1 AA 标准
- 屏幕阅读器可以正确朗读界面内容

### 6.3 响应式设计

- 在桌面浏览器（1024px 及以上）上提供完整功能
- 在平板设备（768px - 1024px）上保持核心功能可用
- 在移动设备（768px 以下）上提供优化的触摸交互和布局
- 侧边栏在窄屏幕下自动切换为覆盖模式
- 设置对话框在移动端使用全屏布局

### 6.4 安全性

- 敏感信息（API Key、认证令牌）不在界面中明文展示
- 分享链接的生成和访问由后端控制权限
- 终端操作受后端权限模型约束
- 文件访问限制在项目目录范围内

### 6.5 可靠性

- 网络连接中断后自动尝试重连
- 未发送的消息在页面刷新后不丢失
- 主题、快捷键、布局等用户偏好设置持久化保存
- 容器重建后数据卷中的会话和配置数据不丢失

### 6.6 兼容性

- 支持主流现代浏览器（Chrome、Firefox、Safari、Edge 的最新两个版本）
- 支持 PWA 安装为桌面或移动端应用
- 支持 macOS、Linux、Windows 桌面平台
- 支持 Docker 容器化部署环境

## 7. 系统边界

### 系统负责的范围

- 提供用户与 AI 后端交互的界面
- 渲染和管理聊天消息、会话、终端等 UI 元素
- 处理用户输入、快捷键、主题等交互逻辑
- 管理本地状态（设置、布局、偏好）
- 与后端通过 API 和 SSE 协议通信

### 系统不负责的范围

- AI 模型的推理和生成（由后端负责）
- 文件系统的实际读写操作（由后端负责）
- 终端命令的实际执行（由后端负责）
- 版本控制操作的实际执行（由后端负责）
- 用户认证和授权管理（由后端负责）
- MCP 服务器的实际实现（由第三方提供）
