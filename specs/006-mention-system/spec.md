# @ 提及系统模块规范

> **模块路径**: `src/features/mention/`
> **版本**: 1.0
> **状态**: 已实现

---

## 1. 模块概述

### 1.1 目的

@ 提及系统为聊天输入框提供资源引用能力。用户在输入框中输入 `@` 字符后，系统弹出自动补全菜单，支持浏览和搜索工作区中的文件、文件夹以及 Agent。选中的资源以可视化标签的形式嵌入输入内容中，并在发送消息时序列化为结构化格式传递给 AI 后端。

### 1.2 解决的问题

- **快速引用文件**: 无需手动输入完整路径，通过菜单浏览或搜索即可引用工作区中的任意文件
- **目录层级导航**: 支持逐层进入子目录查看内容，类似文件浏览器的交互体验
- **Agent 选择**: 在提及菜单中直接选择可用的 Agent，作为消息上下文的一部分
- **可视化标签**: 提及项在输入框中以彩色标签展示，区分不同类型（文件、文件夹、Agent）
- **结构化序列化**: 提及项在发送时转换为 `[[type:value]]` 格式，后端可解析还原

### 1.3 模块边界

| 职责                      | 归属                            |
| ------------------------- | ------------------------------- |
| @ 提及菜单与标签渲染      | **本模块**                      |
| 文件/目录搜索 API         | `api/file.ts`                   |
| Agent 列表获取            | `api/client.ts`                 |
| 输入框编排与事件协调      | `features/chat/`                |
| 设备能力检测（触摸/鼠标） | `hooks/useInputCapabilities.ts` |
| 消息序列化与发送          | `features/chat/`                |

### 1.4 范围

本模块涵盖：

- `@` 触发字符检测与菜单开关控制
- 文件/文件夹浏览与搜索的自动补全菜单
- 提及标签的创建、渲染与交互（点击复制）
- 提及内容的序列化与反序列化
- 编辑器内容重建与光标管理
- 响应式菜单高度计算

本模块不涵盖：

- 消息的发送与接收逻辑
- AI 后端对提及内容的解析与处理
- 斜杠命令系统（由独立模块负责）

## 3. 功能需求

### FR-01：触发检测

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-01          |
| 名称   | @ 触发字符检测 |
| 优先级 | P0             |

**描述**: 在用户输入过程中实时检测 `@` 字符，决定是否打开提及菜单。

**要求**:

- 触发字符 `@` 之前必须是空格、换行符、不可断空格（NBSP）或文本开头
- 触发字符之后不能包含空格或 NBSP，否则关闭菜单
- 光标位置必须在 `@` 之后且中间无空格时才触发
- 检测到有效触发时，记录 `@` 在文本中的起始位置和后续查询字符串
- 未检测到有效触发时，若菜单已打开则关闭

**验收标准**:

- 给定输入 `hello @`，菜单打开，查询字符串为空
- 给定输入 `hello @file`，菜单打开，查询字符串为 `file`
- 给定输入 `email@test.com`，菜单不打开（`@` 前不是空格）
- 给定输入 `@ file`，菜单关闭（`@` 后有空格）
- 给定输入 `@foo bar`，输入空格后菜单关闭

### FR-02：文件与文件夹搜索

| 属性   | 描述            |
| ------ | --------------- |
| 标识   | FR-02           |
| 名称   | 文件/文件夹搜索 |
| 优先级 | P0              |

**描述**: 当用户在 `@` 后输入搜索词时，调用后端文件搜索 API 查找匹配的文件和文件夹。

**要求**:

- 搜索词不包含 `/` 时，调用全局文件搜索接口，限制返回 20 条结果
- 搜索结果按类型分为文件夹和文件两组
- 搜索时传入当前工作目录作为作用域
- 搜索请求使用请求 ID 机制防止竞态条件，旧请求结果被丢弃
- 搜索失败时显示错误提示并清空结果列表

**验收标准**:

- 给定搜索词 `readme`，返回包含 `readme` 的文件和文件夹
- 给定搜索词无匹配结果，显示"无结果"提示
- 快速连续输入搜索词，仅最后一次搜索的结果被展示

### FR-03：目录浏览

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-03        |
| 名称   | 目录层级浏览 |
| 优先级 | P0           |

**描述**: 用户可以在提及菜单中逐层浏览目录结构，类似文件管理器。

**要求**:

- 菜单打开且查询为空时，显示根目录内容（文件夹、文件、Agent）
- 查询中包含 `/` 时，`/` 之前的部分解析为目录路径，之后的部分作为文件名过滤
- 点击文件夹项时，进入该子目录并刷新列表
- 非根目录下，列表顶部显示"返回上级"按钮，展示当前路径
- 返回上级时，记住之前定位的文件夹名称，返回后自动选中该项
- 文件夹项右侧显示 `→` 箭头标识，提示可进入

**验收标准**:

- 给定查询为空，显示根目录下的文件夹、文件和 Agent
- 给定查询 `src/`，显示 `src` 目录下的内容
- 给定查询 `src/compo`，显示 `src` 目录下名称包含 `compo` 的项
- 点击"返回上级"，回到父目录并定位到之前进入的文件夹

### FR-04：Agent 展示

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-04          |
| 名称   | Agent 列表集成 |
| 优先级 | P0             |

**描述**: 提及菜单中集成可用的 Agent 列表，用户可直接选择引用。

**要求**:

- Agent 仅在根目录浏览或搜索匹配时显示
- 仅展示非隐藏且模式为 `subagent` 的 Agent
- Agent 项排在列表最前面，优先于文件夹和文件
- Agent 项显示名称和类型标识，不显示路径
- Agent 名称也参与搜索过滤

**验收标准**:

- 给定根目录且无搜索词，显示所有可用的 subagent
- 给定搜索词 `build`，仅显示名称包含 `build` 的 Agent
- 进入子目录后，Agent 不再显示

### FR-05：自动补全菜单

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-05        |
| 名称   | 自动补全菜单 |
| 优先级 | P0           |

**描述**: 弹出式下拉菜单，展示搜索结果和目录内容，支持键盘和鼠标交互。

**要求**:

- 菜单定位在输入框上方，从底部向上弹出
- 最大高度动态计算，根据输入框在视口中的位置调整，防止被 header 遮挡
- 小屏幕下最大高度不超过可用空间，桌面端默认最大 320px
- 监听窗口 resize 和虚拟视口变化（移动端键盘弹出/收起），重新计算高度
- 支持键盘导航：上箭头选中上一项、下箭头选中下一项、Enter 确认、Esc 关闭
- 鼠标悬停自动切换选中项
- 点击菜单外部区域关闭菜单
- 加载状态显示加载动画
- 空状态显示友好提示（搜索无结果 vs 空目录）
- 底部显示键盘操作提示（仅桌面端）
- 已选择的项从列表中排除

**验收标准**:

- 菜单打开时，第一项默认选中
- 键盘上下箭头移动选中项，边界不越界
- 移动端键盘弹出后，菜单高度自动缩减
- 点击菜单外部，菜单关闭

### FR-06：提及标签渲染

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-06          |
| 名称   | 可视化提及标签 |
| 优先级 | P0             |

**描述**: 选中提及项后，在输入框中插入一个不可编辑的彩色标签。

**要求**:

- 标签格式：`@Type: displayName`，例如 `@File: README.md`
- 标签设置为 `contentEditable="false"`，不可被用户编辑
- 不同类型使用不同颜色方案：
  - Agent：警告色（黄色系）
  - File：信息色（蓝色系）
  - Folder：成功色（绿色系）
- 标签包含 `data-mention-type`、`data-mention-value`、`data-mention-display` 三个数据属性
- 标签后自动插入一个空格，与后续文本分隔
- 标签最大宽度 200px，超出时截断显示
- 悬停时亮度降低，点击时轻微缩放，提供交互反馈

**验收标准**:

- 选中文件后，输入框中出现 `@File: 文件名` 标签
- 标签不可被光标分割或编辑
- 不同类型标签颜色不同，视觉可区分

### FR-07：提及序列化

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-07          |
| 名称   | 提及内容序列化 |
| 优先级 | P0             |

**描述**: 将输入框中的提及标签转换为结构化文本格式，供消息发送时使用。

**要求**:

- 序列化格式：`[[type:value]]`，其中 type 为 `agent`、`file` 或 `folder`，value 为完整路径或名称
- 序列化时遍历编辑器 DOM 树，文本节点保留原文，提及标签转换为序列化格式
- 提供反序列化解析函数，将 `[[type:value]]` 格式还原为文本片段和提及项的交替数组
- 提供提取函数，从序列化文本中提取所有提及项列表
- 提供剥离函数，移除序列化文本中的所有提及标记，返回纯文本

**验收标准**:

- 给定输入框中包含一个文件提及，序列化结果为 `[[file:/absolute/path/to/file]]`
- 给定序列化文本 `[[agent:build]]hello[[file:/src/main.ts]]`，解析返回三个片段：文本 `hello` 前后的两个提及
- 给定序列化文本，提取函数返回所有提及项的数组
- 给定序列化文本，剥离函数返回 `hello`

### FR-08：提及标签点击复制

| 属性   | 描述             |
| ------ | ---------------- |
| 标识   | FR-08            |
| 名称   | 点击复制完整路径 |
| 优先级 | P1               |

**描述**: 用户点击提及标签时，将其完整值（绝对路径或 Agent 名称）复制到剪贴板。

**要求**:

- 点击标签时阻止事件冒泡和默认行为
- 复制成功后，标签内短暂显示勾选图标（1.2-1.5 秒），然后恢复原文
- 复制失败时调用错误处理回调，不中断用户操作
- 标签的 title 属性提示"Click to copy: value"

**验收标准**:

- 点击文件提及标签，完整绝对路径被复制到剪贴板
- 复制成功后显示勾选图标，1.5 秒后自动消失
- 点击 Agent 提及标签，Agent 名称被复制到剪贴板

### FR-09：路径处理

| 属性   | 描述             |
| ------ | ---------------- |
| 标识   | FR-09            |
| 名称   | 路径标准化与转换 |
| 优先级 | P0               |

**描述**: 统一处理不同操作系统的路径格式，确保提及值的正确性。

**要求**:

- 路径标准化：统一使用 `/` 作为分隔符，移除重复斜杠
- 相对路径转绝对路径：结合根路径配置，将相对路径转换为绝对路径
- Windows 绝对路径识别：检测 `C:` 格式的盘符前缀
- 文件名提取：从完整路径中提取最后一段作为显示名称
- file:// URL 生成：根据路径类型生成正确的 file:// URL（Windows 用 `file:///`，Unix 用 `file://`）

**验收标准**:

- 给定相对路径 `src/main.ts` 和根路径 `/project`，转换为 `/project/src/main.ts`
- 给定 Windows 路径 `C:\Users\test`，标准化为 `C:/Users/test`
- 给定路径 `/project/src/utils/helper.ts`，提取文件名 `helper.ts`

## 4. 关键实体

### 4.1 MentionItem（提及项）

表示一个可被引用的资源。

| 属性           | 类型        | 说明                                      |
| -------------- | ----------- | ----------------------------------------- |
| `type`         | MentionType | 提及类型：`agent`、`file`、`folder`       |
| `value`        | string      | 完整值（绝对路径或 Agent 名称）           |
| `displayName`  | string      | 显示名称（文件名或 Agent 名称）           |
| `relativePath` | string?     | 相对路径（用于菜单中显示，文件/文件夹项） |

### 4.2 MentionType（提及类型）

枚举提及资源的种类。

| 值       | 说明                 | 颜色方案 |
| -------- | -------------------- | -------- |
| `agent`  | AI Agent（子智能体） | 警告色   |
| `file`   | 工作区文件           | 信息色   |
| `folder` | 工作区文件夹         | 成功色   |

### 4.3 MentionMenuState（菜单状态）

描述提及菜单的当前状态。

| 属性         | 类型    | 说明                       |
| ------------ | ------- | -------------------------- |
| `isOpen`     | boolean | 菜单是否打开               |
| `query`      | string  | `@` 之后的搜索词           |
| `startIndex` | number  | `@` 字符在文本中的索引位置 |
| `position`   | object? | 菜单位置坐标（可选）       |

### 4.4 ParsedSegment（解析片段）

序列化文本解析后的片段，用于反序列化渲染。

| 属性           | 类型         | 说明                          |
| -------------- | ------------ | ----------------------------- |
| `type`         | string       | 片段类型：`text` 或 `mention` |
| `content`      | string       | 片段内容（文本内容或提及值）  |
| `mentionType`  | MentionType? | 提及类型（仅 mention 片段）   |
| `mentionValue` | string?      | 提及完整值（仅 mention 片段） |

### 4.5 MentionConfig（提及配置）

提及系统的可配置参数。

| 属性            | 类型    | 默认值 | 说明                         |
| --------------- | ------- | ------ | ---------------------------- |
| `trigger`       | string  | `@`    | 触发字符                     |
| `rootPath`      | string  | `''`   | 项目根路径，用于生成绝对路径 |
| `allowMultiple` | boolean | `true` | 是否允许多个提及             |

### 4.6 MentionMenuHandle（菜单控制器）

暴露给父组件的菜单操作方法。

| 方法                     | 说明                         |
| ------------------------ | ---------------------------- |
| `moveUp()`               | 选中上一项                   |
| `moveDown()`             | 选中下一项                   |
| `selectCurrent()`        | 确认选中当前项               |
| `enterFolder()`          | 进入当前选中的文件夹         |
| `goBack()`               | 返回上级目录                 |
| `getSelectedItem()`      | 获取当前选中项               |
| `setRestoreFolder(name)` | 设置返回上级时定位的文件夹名 |

## 5. 交互流程

### 5.1 完整提及流程

```
用户在输入框中输入文本
        │
        ▼
  检测到 @ 字符（前面是空格/开头）
        │
        ▼
  打开提及菜单，显示根目录内容
  （文件夹 + 文件 + Agent）
        │
        ▼
  用户输入搜索词 或 点击文件夹导航
        │
        ├── 输入搜索词 ──► 调用文件搜索 API ──► 显示匹配结果
        │
        └── 点击文件夹 ──► 进入子目录 ──► 显示子目录内容
                                │
                                └── 点击"返回上级" ──► 回到父目录
        │
        ▼
  用户选中某一项（键盘 Enter 或鼠标点击）
        │
        ▼
  重建编辑器内容：
  - @ 之前的文本保留
  - 插入提及标签（contentEditable=false）
  - 插入空格 + @ 之后的文本
        │
        ▼
  关闭菜单，聚焦编辑器，光标移至末尾
        │
        ▼
  用户继续输入或发送消息
        │
        ▼
  发送时序列化编辑器内容：
  提及标签 → [[type:value]] 格式
```

### 5.2 触发条件判定

```
文本: "hello @world"
              ↑ 光标在此

1. 查找光标前最后一个 @ → 找到
2. 检查 @ 之前的字符 → 是空格 ✓
3. 检查 @ 之后到光标之间 → 无空格 ✓
4. 结果：触发，查询字符串 = "world"
```

## 8. 非功能需求

### 8.1 性能

- 文件搜索请求使用请求 ID 去重，快速连续输入时仅保留最后一次请求结果
- 菜单高度计算使用 `requestAnimationFrame`，避免布局抖动
- 目录浏览时，文件夹和文件分组排序，Agent 优先展示

### 8.2 响应式适配

- 菜单最大高度根据输入框在视口中的位置动态计算
- 监听 `resize` 和 `visualViewport.resize` 事件（移动端键盘弹出/收起）
- 桌面端默认最大高度 320px，移动端根据可用空间缩减
- 键盘操作提示仅在桌面端（`md` 断点以上）显示

### 8.3 国际化

- 所有用户可见文本通过 i18n 键值管理
- 支持 `commands` 和 `common` 两个命名空间
- 提及类型标签（Agent/File/Folder）通过翻译键获取

### 8.4 可访问性

- 提及标签设置 `contentEditable="false"`，防止被屏幕阅读器误读为可编辑内容
- 菜单项使用 `<button>` 元素，天然支持键盘焦点
- 键盘导航支持：上下箭头移动焦点、Enter 确认、Esc 关闭

## 10. 架构决策记录

### ADR-001：为什么使用 `[[type:value]]` 作为序列化格式

**决策**: 提及项序列化为 `[[type:value]]` 格式，例如 `[[file:/project/src/main.ts]]`。

**理由**:

- 双括号 `[[` 和 `]]` 在日常文本中极少出现，降低冲突概率
- `type:value` 结构清晰，易于正则解析
- 后端可据此还原提及的类型和完整值
- 与纯文本混合时不会产生歧义

### ADR-002：为什么提及标签使用 `contentEditable="false"`

**决策**: 提及标签 DOM 元素设置 `contentEditable="false"`。

**理由**:

- 防止用户在标签内部编辑，破坏提及结构
- 光标可以跳过标签，不会停留在标签中间
- 浏览器原生支持，无需
- 序列化时通过 `data-*` 属性还原提及信息

### ADR-003：为什么菜单高度需要动态计算

**决策**: 菜单最大高度根据输入框在视口中的位置实时计算，而非固定值。

**理由**:

- 移动端虚拟键盘弹出时，可用视口高度大幅缩减
- 输入框可能位于页面不同位置（多窗格模式下）
- 固定高度可能导致菜单被 header 遮挡或超出视口
- 使用 `requestAnimationFrame` + `getBoundingClientRect` 确保计算准确

### ADR-004：为什么 Agent 仅在根目录显示

**决策**: Agent 项仅在浏览根目录或搜索匹配时显示，进入子目录后隐藏。

**理由**:

- Agent 不属于文件系统层级结构
- 进入子目录后用户意图是浏览文件，Agent 会干扰搜索结果
- 根目录下 Agent 作为快捷入口，方便快速引用

## 11. 风险与缓解

| 风险                                    | 影响                             | 缓解措施                                     |
| --------------------------------------- | -------------------------------- | -------------------------------------------- |
| 快速连续输入导致竞态条件                | 旧搜索结果覆盖新结果             | 请求 ID 机制，递增 ID 丢弃过期结果           |
| 移动端键盘弹出遮挡菜单                  | 用户无法看到或操作菜单           | 动态计算最大高度，监听 visualViewport 变化   |
| 提及标签在 contentEditable 中被意外删除 | 提及信息丢失                     | 标签设置 `contentEditable="false"`，光标跳过 |
| 大目录加载缓慢                          | 菜单长时间显示加载状态           | 搜索结果限制 20 条，目录浏览按需加载         |
| 序列化格式与用户输入冲突                | 用户输入的 `[[file:x]]` 被误解析 | 该格式在日常输入中极少出现，风险可接受       |
