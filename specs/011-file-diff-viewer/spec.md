# 文件 Diff 查看器模块规范 (File Diff Viewer Specification)

> **模块路径**: `src/components/DiffView.tsx`, `src/components/DiffViewer.tsx`, `src/components/DiffModal.tsx`, `src/components/MultiFileDiffModal.tsx`, `src/components/SessionChangesPanel.tsx`, `src/components/FileExplorer.tsx`, `src/utils/diffUtils.ts`, `src/store/changeScopeStore.ts`
> **版本**: 1.0
> **状态**: 已实现

---

## 1. 模块概述

### 1.1 目的

文件 Diff 查看器模块负责 OpenCodeUI 中所有代码变更的可视化展示。用户可通过该模块查看 AI 在会话中对工作区文件所做的修改，支持单文件 diff 浏览、多文件 diff 对比、文件树变更指示、会话级变更汇总等多种场景。

### 1.2 解决的问题

- **单文件变更查看**: 在聊天消息中内嵌展示单个文件的修改内容，支持展开/折叠
- **并排与统一视图**: 提供 split（左右并排）和 unified（上下合并）两种 diff 展示模式
- **语法高亮**: 在 diff 内容中保留代码语法着色，提升可读性
- **词级差异高亮**: 在行级别变更的基础上，进一步高亮行内具体被修改的词语
- **多文件浏览**: 全屏模态框中左侧文件列表、右侧 diff 内容，快速切换浏览
- **变更范围过滤**: 支持按会话、轮次、git 工作区、分支差异等不同范围查看变更
- **文件树变更指示**: 在文件浏览器中通过颜色标记显示文件的 git 状态（新增/修改/删除）

### 1.3 模块边界

| 职责              | 归属                            |
| ----------------- | ------------------------------- |
| Diff 行计算与配对 | **本模块** (`DiffViewer.tsx`)   |
| Unified diff 解析 | **本模块** (`diffUtils.ts`)     |
| 语法高亮集成      | `hooks/useSyntaxHighlight.ts`   |
| 虚拟滚动          | `hooks/useDynamicVirtualScroll` |
| 全屏容器          | `components/FullscreenViewer`   |
| 文件内容获取 API  | `api/file.ts`                   |
| 会话 diff API     | `api/session.ts`                |
| VCS 信息 API      | `api/vcs.ts`                    |
| 变更范围状态管理  | **本模块** (`changeScopeStore`) |
| 文件状态获取      | `api/file.ts` (git status)      |

### 1.4 范围

本模块涵盖：

- 单文件 diff 渲染组件（内嵌式与全屏式）
- 核心 DiffViewer 组件（split/unified 双模式）
- 多文件 diff 全屏模态框
- 会话变更面板（文件列表 + diff 预览）
- 文件浏览器中的变更状态指示
- 变更范围过滤（session/turn/git/branch）
- Context 行折叠与展开
- 虚拟滚动优化

本模块不涵盖：

- 文件内容的编辑与保存
- Git 提交与分支管理操作
- 文件系统的增删改操作

## 3. 功能需求

### FR-01：Unified Diff 渲染

| 属性   | 描述               |
| ------ | ------------------ |
| 标识   | FR-01              |
| 名称   | 统一 diff 渲染引擎 |
| 优先级 | P0                 |

**描述**: 核心 diff 渲染能力，支持将 before/after 两段文本计算为行级差异并以可视化方式展示。

**要求**:

- 接受 before 和 after 两段文本作为输入，或接受 unified diff 格式字符串
- 使用行级 diff 算法计算变更，生成包含新增、删除、上下文三种类型的行序列
- 在 split 模式下，左右两列分别展示 before 和 after 内容，变更行配对显示
- 在 unified 模式下，单列展示所有行，删除行在上、新增行在下、上下文行居中
- 纯新增文件（before 为空）或纯删除文件（after 为空）时，自动降级为 unified 模式
- 每行显示对应的行号，删除行显示旧行号，新增行显示新行号，上下文行同时显示两者

**验收标准**:

- 给定 before="line1\nline2\nline3" 和 after="line1\nmodified\nline3"，split 模式左侧显示 line2 为删除，右侧显示 modified 为新增
- 给定 unified diff 格式字符串，正确解析并渲染对应的 diff 内容
- 给定纯新增文件，自动使用 unified 模式展示

### FR-02：语法高亮 Diff

| 属性   | 描述         |
| ------ | ------------ |
| 标识   | FR-02        |
| 名称   | 语法高亮集成 |
| 优先级 | P0           |

**描述**: 在 diff 内容中应用代码语法高亮，使变更内容保持可读性。

**要求**:

- 根据文件路径自动检测编程语言
- 支持显式传入语言参数覆盖自动检测
- 使用语法高亮引擎对 before 和 after 内容分别进行 token 化
- 高亮结果与 diff 行号对齐，确保每行使用正确的 token 集合
- 非代码文件（如纯文本、配置文件）降级为无高亮纯文本展示
- 面板调整大小过程中暂停高亮计算，避免性能浪费

**验收标准**:

- 给定 TypeScript 文件 diff，代码关键字、字符串、注释等以不同颜色显示
- 给定未知扩展名的文件，以纯文本形式展示，无语法着色
- 显式传入 `language="json"` 时，无论文件扩展名如何都使用 JSON 高亮

### FR-03：词级差异高亮

| 属性   | 描述          |
| ------ | ------------- |
| 标识   | FR-03         |
| 名称   | 行内词级 diff |
| 优先级 | P0            |

**描述**: 在行级别变更的基础上，进一步计算行内词语级别的差异，对具体被修改的词语进行背景高亮。

**要求**:

- 对配对的删除行和新增行进行词级别 diff 计算
- 删除行中被移除的词语使用红色背景高亮
- 新增行中新增的词语使用绿色背景高亮
- 当词级 diff 过于碎片化（公共内容占比低于 40% 且总长度超过 10 字符）时，跳过词级高亮，避免视觉混乱
- 相邻的同类型词级变更合并展示，减少碎片
- 面板调整大小过程中跳过词级 diff 计算

**验收标准**:

- 给定行 `const name = "hello"` 变更为 `const name = "world"`，`"hello"` 和 `"world"` 分别以红/绿背景高亮
- 给定整行完全重写且无公共词语的情况，不显示词级高亮，仅显示行级别的增删
- 给定仅修改行内一个单词的情况，该单词被精确高亮

### FR-04：多文件 Diff 模态框

| 属性   | 描述               |
| ------ | ------------------ |
| 标识   | FR-04              |
| 名称   | 多文件 diff 浏览器 |
| 优先级 | P0                 |

- 加载状态显示加载动画，错误状态显示友好提示

**验收标准**:

- 打开模态框后，左侧列出会话中所有被修改的文件
- 点击不同文件，右侧 diff 内容随之切换

### FR-06：变更范围过滤

| 属性   | 描述           |
| ------ | -------------- |
| 标识   | FR-06          |
| 名称   | 变更范围选择器 |
| 优先级 | P0             |

**描述**: 在会话变更面板中，用户可选择不同的变更范围来查看不同粒度的改动。

**要求**:

- 支持四种变更范围模式：
  - **session**: 当前会话产生的所有变更
  - **turn**: 最近一轮对话（一问一答）产生的变更
  - **git**: 相对于上次 git 提交的工作区差异
  - **branch**: 当前分支相对于默认分支的差异
- 可用选项根据项目状态动态生成：无 VCS 时不显示 git/branch 选项，当前分支等于默认分支时不显示 branch 选项
- 默认优先选择 session 模式
- 每种模式有独立的缓存，切换模式时不重复请求已加载的数据
- 变更范围状态按会话 ID 隔离，不同会话可保持各自的模式选择
- 模式切换时自动校准选中文件和高亮状态

**验收标准**:

- 项目有 VCS 且当前分支不同于默认分支时，显示 session/turn/git/branch 四个选项
- 项目无 VCS 时，不显示变更范围选择器
- 从 session 切换到 git 再切回 session 时，session 的 diff 数据无需重新加载
- 切换会话后，变更范围模式重置为默认值

### FR-08：Context 行折叠

| 属性   | 描述               |

| 标识   | FR-08              |
| 名称   | 上下文行折叠与展开 |
| 优先级 | P1                 |

## 4. 关键实体

### 4.1 FileDiff（文件差异）

表示单个文件的变更信息。

| 属性        | 类型    | 说明                                     |
| ----------- | ------- | ---------------------------------------- |
| `file`      | string  | 文件路径（相对路径）                     |
| `patch`     | string? | Unified diff 格式的补丁字符串            |
| `before`    | string? | 修改前的文件内容（旧版后端兼容）         |
| `after`     | string? | 修改后的文件内容（旧版后端兼容）         |
| `additions` | number  | 新增行数                                 |
| `deletions` | number  | 删除行数                                 |
| `status`    | string? | 文件状态：`added`、`modified`、`deleted` |

### 4.2 DiffLine（Diff 行）

diff 计算后生成的单行数据。

| 属性                 | 类型     | 说明                                        |
| -------------------- | -------- | ------------------------------------------- |

### 5.1 组件层次

```

    │       └── content (代码内容)

DiffView (内嵌式 diff 组件)
    │
    ├── 折叠头部 (文件名 + 统计 + 放大按钮)
    ├── DiffViewer (内嵌内容)
    └── FullscreenViewer (全屏弹窗)
            └── DiffViewer

DiffModal (单文件全屏 diff)
    │
    └── FullscreenViewer
            └── DiffViewer

MultiFileDiffModal (多文件全屏 diff)
    │
    └── FullscreenViewer
            ├── 侧边栏 (文件列表)
            └── DiffViewer (当前选中文件)

SessionChangesPanel (会话变更面板)
    │
    ├── 头部 (统计 + 范围选择 + 视图切换 + 刷新)
    ├── 文件列表 (树形/扁平)
    └── DiffPreviewPanel (diff 预览区)
            ├── PreviewTabsBar (多标签)
            ├── DiffViewer
            └── FullscreenViewer (全屏)

FileExplorer (文件浏览器)
    │
    ├── FileTreeItem (文件树节点，含变更状态颜色)
    └── FilePreview (文件内容预览)
```

### 5.2 数据流

```
API 层 (getSessionDiff / getVcsDiff / getLastTurnDiff)
        │
        ▼
    FileDiff[] (扁平变更列表)
        │
        ├──► MultiFileDiffModal: 直接渲染文件列表
        │
        ├──► SessionChangesPanel:
        │       │
        │       ├── buildChangesTree() ──► ChangesTreeNode[] (树形结构)
        │       │
        │       └── 扁平列表模式: 直接渲染
        │
        └──► FileExplorer:
                │
                └── fileStatus Map ──► FileTreeItem 状态颜色

    changeScopeStore (变更范围状态)
        │
        └── 按 sessionId 存储 ChangeScopeMode
            └── useSessionChangeScope() Hook 驱动 UI 更新
```

### 5.3 Diff 计算流程

```
before 文本 + after 文本
        │
        ▼
    diffLines() ──► 变更块数组 (added/removed/unchanged)
        │
        ▼
    computePairedLines() / computeUnifiedLines()
        │
        ├──► split 模式: PairedLine[]
        │       └── 配对删除/新增行，计算词级 diff
        │
        └──► unified 模式: UnifiedLine[]
                └── 按顺序排列所有行

        │
        ▼
    collapseContextPaired() / collapseContextUnified()
        │
        └── 折叠连续 context 行 ──► (PairedLine | CollapsedLine)[]

        │
        ▼
    虚拟滚动 ──► 仅渲染可视区域内的行

        │
        ▼
    LineContent 渲染
        ├── highlightedContent (词级 diff HTML)
        ├── tokens (语法高亮 token)
        └── 纯文本 (降级)
```

## 10. 架构决策记录

### ADR-001：为什么 split 模式在纯新增/纯删除时自动降级为 unified

**决策**: 当 before 为空（纯新增）或 after 为空（纯删除）时，强制使用 unified 模式。

**理由**:

- split 模式的核心价值在于并排对比，纯新增或纯删除时另一侧完全空白，失去对比意义
- unified 模式在单侧内容场景下空间利用率更高
- 减少用户手动切换的操作成本

### ADR-002：为什么使用虚拟滚动而非全量渲染

**决策**: DiffViewer 默认使用虚拟滚动，仅渲染可视区域内的行。

**理由**:

- 工作区文件可能包含数千甚至上万行代码
- 全量渲染会导致 DOM 节点过多，严重影响性能
- 虚拟滚动将 DOM 节点数控制在可视范围 + overscan 内
- 自动换行场景下切换为动态高度虚拟滚动，适配不等高行

### ADR-003：为什么词级 diff 需要碎片化检测

**决策**: 当词级 diff 的公共内容占比低于 40% 且总长度超过 10 字符时，跳过词级高亮。

**理由**:

- 整行完全重写时，词级 diff 会产生大量碎片化高亮
- 碎片化高亮视觉上比行级高亮更混乱，反而降低可读性
- 设置阈值后，仅在改动局部且有意义时展示词级高亮

### ADR-004：为什么变更范围状态按会话 ID 隔离

**决策**: changeScopeStore 使用 Map<sessionId, ChangeScopeMode> 存储，每个会话独立维护自己的变更范围选择。

**理由**:

- 不同会话可能处于不同的开发阶段，用户关注的变更范围不同
- 切换会话后恢复该会话上次的选择，符合用户心智模型
- 避免全局单例导致的状态污染

### ADR-005：为什么 Context 折叠使用起始 ID 而非内容哈希

**决策**: 折叠区域使用在原始行数组中的起始索引作为唯一 ID，展开状态通过 Set<ID> 管理。

**理由**:

- 起始索引在 diff 重算前保持稳定，避免展开状态丢失
- 内容哈希在 diff 变化时可能冲突或失效
- Set 结构提供 O(1) 的展开状态查询

## 11. 风险与缓解

| 风险                                   | 影响                 | 缓解措施                                                          |
| -------------------------------------- | -------------------- | ----------------------------------------------------------------- |
| 超大文件（10 万行+）导致 diff 计算耗时 | 打开 diff 时界面卡顿 | diff 计算在 useMemo 中执行，避免阻塞渲染；考虑后续引入 Web Worker |
| 快速切换文件导致多个并发 API 请求      | 旧请求结果覆盖新请求 | 请求 ID 递增机制，丢弃过期结果                                    |
| unified diff 格式不规范导致解析失败    | diff 内容无法展示    | 解析失败时降级为纯文本展示                                        |
| 词级 diff 在长行上性能下降             | 渲染延迟             | 碎片化阈值检测跳过无意义的词级计算                                |
| 虚拟滚动在动态换行时高度计算不准确     | 行错位或滚动条跳动   | 使用动态高度虚拟滚动方案，逐行测量实际高度                        |
| 变更面板中树形结构构建耗时（大量文件） | 面板打开时短暂卡顿   | 树形构建在 useMemo 中缓存，仅在 diffs 变化时重算                  |
