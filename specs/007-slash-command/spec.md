# 斜杠命令系统规范

> 模块编号：007-slash-command
> 状态：已实现
> 最后更新：2026-04-12

---

## 1. 模块概述

### 1.1 目的

斜杠命令系统为用户提供了一种在聊天输入框中通过 `/` 前缀快速触发特殊操作的方式。用户在输入框中键入 `/` 后，系统自动弹出命令选择菜单，展示可用命令列表，支持实时过滤和键盘导航，选中后执行对应命令。

### 1.2 解决的问题

- **快速操作入口**：无需在界面中寻找按钮或菜单，通过键盘即可触发常用操作
- **命令发现**：自动展示所有可用命令及其描述，降低学习成本
- **统一交互模式**：与 `@` 提及系统保持一致的弹出菜单交互范式
- **前后端命令融合**：后端 API 提供的命令与前端内置命令自动合并，前端命令作为后端不可用时的降级方案

### 1.3 范围

本模块涵盖：

- 斜杠命令选择菜单组件的渲染与交互
- 命令列表的加载、缓存与过滤
- 键盘导航与鼠标选择
- 命令元数据展示（名称、描述、快捷键）
- 动态高度计算与响应式布局
- 点击外部区域自动关闭

本模块不涵盖：

- 命令的具体执行逻辑（由会话 API 层负责）
- 输入框中 `/` 触发检测逻辑（由输入组件负责）
- 后端命令的定义与注册

## 3. 功能需求

### FR-01：触发检测

**描述**：当用户在聊天输入框中键入 `/` 字符时，系统识别为斜杠命令触发信号，准备展示命令菜单。

**要求**：

- 触发信号由输入组件负责检测，本模块接收 `isOpen` 和 `query` 两个参数
- `query` 为 `/` 之后的文本内容，用于过滤命令
- 菜单仅在 `isOpen` 为真时渲染，否则返回空

**验收标准**：

- 给定 `isOpen` 为假，菜单不渲染任何内容
- 给定 `isOpen` 为真，菜单正常渲染

### FR-02：命令列表加载

**描述**：菜单打开时，从后端 API 加载可用命令列表，并与前端内置命令合并。

**要求**：

- 菜单打开时发起命令列表请求，携带当前工作目录参数
- 命令来源分为两类：后端 API 返回的命令（source 为 `api`）和前端内置命令（source 为 `frontend`）
- 前端内置命令包括 `new`（新建会话）和 `compact`（压缩会话），仅在后端未提供同名命令时补充
- 加载过程中显示加载状态提示
- 加载失败时命令列表置空，但不阻断前端内置命令的展示
- 请求带有防重入机制，同一时刻仅发起一次请求

**验收标准**：

- 给定后端正常返回，菜单展示后端命令与前端内置命令的合并结果
- 给定后端不可达，菜单仅展示前端内置命令
- 给定加载过程中，菜单显示加载提示
- 给定后端返回空列表，菜单展示前端内置命令

### FR-03：命令过滤

**描述**：根据用户键入的查询文本实时过滤命令列表，支持名称和描述的不区分大小写匹配。

**要求**：

- 过滤条件：命令名称或描述包含查询文本（不区分大小写）
- 查询文本为空时，展示全部命令
- 过滤结果实时更新，无延迟
- 查询文本变化时，选中索引重置为第一项

**验收标准**：

- 给定查询文本 "comp"，仅展示名称或描述包含 "comp" 的命令
- 给定查询文本为空，展示全部命令
- 给定无匹配命令，展示"无匹配命令"提示
- 给定查询文本变化后，选中项重置为第一项

### FR-04：命令选择与执行

**描述**：用户通过点击或键盘导航选择命令后，触发执行回调。

**要求**：

- 点击命令项直接触发 `onSelect` 回调，传入选中的命令对象
- 键盘导航通过暴露的句柄方法实现：`moveUp`、`moveDown`、`selectCurrent`
- `selectCurrent` 执行当前高亮项的 `onSelect` 回调
- `getSelectedCommand` 返回当前高亮的命令对象，供父组件使用
- 选中索引边界保护：上移不低于 0，下移不超过过滤后列表最后一项

**验收标准**：

- 给定点击命令项，`onSelect` 被调用且参数为对应命令
- 给定调用 `moveDown` 三次，选中索引递增 3（不超过边界）
- 给定调用 `moveUp` 在索引 0 时，选中索引保持 0
- 给定调用 `selectCurrent`，当前高亮命令被传递给 `onSelect`

### FR-05：命令元数据展示

**描述**：每个命令项展示其名称、描述和可选的快捷键绑定。

**要求**：

- 命令名称以等宽字体显示，前缀 `/`，固定宽度列对齐
- 命令描述以较小字号显示在名称右侧，超出时截断
- 快捷键（keybind）以等宽字体显示在最右侧，仅当命令定义了 keybind 时展示
- 命令名称列宽度根据最长命令名动态计算，范围 10ch 到 18ch
- 当前高亮项使用强调色背景区分

**验收标准**：

- 给定命令有描述，描述文本正常显示
- 给定命令无描述，不显示描述区域
- 给定命令有 keybind，快捷键显示在右侧
- 给定命令无 keybind，不显示快捷键区域
- 高亮项背景色与非高亮项有明显区分

### FR-06：动态高度与响应式

**描述**：菜单高度根据可用空间动态计算，防止在小屏幕上被其他 UI 元素遮挡。

**要求**：

- 菜单最大高度默认值为 `min(320px, calc(100dvh - 10rem))`
- 当可用空间小于 360px 且大于 0 时，使用动态计算的高度
- 窗口大小变化时重新计算可用高度
- 菜单关闭时重置动态高度
- 使用 `requestAnimationFrame` 确保计算在布局完成后执行

**验收标准**：

- 给定充足垂直空间，菜单使用默认最大高度 320px
- 给定受限垂直空间（如屏幕顶部附近），菜单高度自动缩减
- 给定窗口大小变化，菜单高度重新计算
- 给定菜单关闭后再次打开，高度计算正确重置

### FR-07：键盘导航句柄

**描述**：组件通过 `forwardRef` 暴露导航方法，供父组件在键盘事件中调用。

**要求**：

- `moveUp()`：将选中索引减 1，最小为 0
- `moveDown()`：将选中索引加 1，最大为过滤后列表长度减 1
- `selectCurrent()`：触发当前选中项的选择回调
- `getSelectedCommand()`：返回当前选中的命令对象，无选中时返回 null

**验收标准**：

- 给定过滤后有 3 项命令，连续调用 `moveDown` 3 次，索引停在 2
- 给定索引为 0 时调用 `moveUp`，索引保持 0
- 给定无过滤结果时调用 `selectCurrent`，不触发回调
- 给定有选中项时调用 `getSelectedCommand`，返回对应命令对象

### FR-08：点击外部关闭

**描述**：菜单打开时，点击菜单外部区域自动关闭菜单。

**要求**：

- 使用 `pointerdown` 事件检测外部点击
- 点击目标不在菜单元素内时触发 `onClose` 回调
- 菜单关闭时移除事件监听器，避免内存泄漏

**验收标准**：

- 给定菜单打开状态，点击菜单外部，`onClose` 被调用
- 给定菜单打开状态，点击菜单内部，`onClose` 不被调用
- 给定菜单关闭后，无残留事件监听器

### FR-09：空状态提示

**描述**：当命令列表为空或过滤后无结果时，展示友好的提示信息。

**要求**：

- 加载完成后过滤结果为空且查询文本非空时，显示"无匹配命令"提示
- 加载完成后命令列表本身为空时，显示"无可用命令"提示
- 提示文本居中对齐，使用次要文本颜色

**验收标准**：

- 给定查询 "xyz" 无匹配结果，显示"无匹配命令"
- 给定后端和前端均无命令，显示"无可用命令"

### FR-10：操作提示

**描述**：菜单底部展示键盘操作提示，仅在桌面端可见。

**要求**：

- 提示内容包括：上下箭头导航、回车执行、ESC 取消
- 仅在桌面端（md 断点以上）显示
- 使用小字号和次要文本颜色

**验收标准**：

- 给定桌面端视口，底部显示操作提示
- 给定移动端视口，底部不显示操作提示

## 4. 关键实体

### 4.1 Command（命令）

| 属性        | 类型                | 说明                          |
| ----------- | ------------------- | ----------------------------- |
| name        | string              | 命令名称，如 `compact`、`new` |
| description | string（可选）      | 命令描述，用于展示和过滤      |
| keybind     | string（可选）      | 快捷键绑定，如 `Ctrl+K`       |
| source      | `frontend` \| `api` | 命令来源：前端内置或后端 API  |

**行为**：

- 来源为 `api` 的命令由后端 `GET /command` 接口提供
- 来源为 `frontend` 的命令由前端硬编码提供，作为后端不可用时的降级
- 同名命令以后端为准，前端命令不覆盖后端命令

### 4.2 SlashCommandMenu（命令菜单组件）

**Props**：

| 属性     | 类型                       | 说明                        |
| -------- | -------------------------- | --------------------------- |
| isOpen   | boolean                    | 菜单是否打开                |
| query    | string                     | `/` 之后的查询文本          |
| rootPath | string（可选）             | 当前工作目录，用于 API 调用 |
| onSelect | (command: Command) => void | 命令选中回调                |
| onClose  | () => void                 | 菜单关闭回调                |

**暴露句柄（SlashCommandMenuHandle）**：

| 方法               | 返回值          | 说明             |
| ------------------ | --------------- | ---------------- |
| moveUp             | void            | 上移选中项       |
| moveDown           | void            | 下移选中项       |
| selectCurrent      | void            | 执行当前选中项   |
| getSelectedCommand | Command \| null | 获取当前选中命令 |

**内部状态**：

| 状态             | 类型                | 说明               |
| ---------------- | ------------------- | ------------------ |
| commands         | Command[]           | 完整命令列表       |
| selectedIndex    | number              | 当前选中索引       |
| loading          | boolean             | 是否正在加载命令   |
| dynamicMaxHeight | number \| undefined | 动态计算的最大高度 |

**派生状态**：

| 状态               | 计算方式                                       |
| ------------------ | ---------------------------------------------- |
| filteredCommands   | 根据 query 不区分大小写过滤 commands           |
| activeIndex        | selectedIndex 与 filteredCommands 长度的较小值 |
| commandColumnWidth | 基于最长命令名动态计算，范围 10ch 到 18ch      |

## 5. 交互流程

```
用户在输入框键入 "/"
        │
        ▼
输入组件设置 isOpen=true, query=""
        │
        ▼
SlashCommandMenu 渲染
        │
        ├── 发起 getCommands(rootPath) 请求
        │       │
        │       ├── 成功 → 合并后端与前端命令 → 更新 commands 状态
        │       └── 失败 → 命令列表置空（前端命令仍可用）
        │
        ▼
展示命令列表（加载中 / 空状态 / 命令项）
        │
        ▼
用户输入过滤文本
        │
        ▼
query 更新 → 过滤命令列表 → 重置选中索引为 0
        │
        ▼
用户选择命令
        │
        ├── 鼠标点击 → 直接触发 onSelect(command)
        ├── 鼠标悬停 → 更新选中索引
        ├── 键盘 ↑ → moveUp()
        ├── 键盘 ↓ → moveDown()
        └── 键盘 Enter → selectCurrent()
        │
        ▼
onSelect 回调执行 → 父组件处理命令执行逻辑
        │
        ▼
菜单关闭（onClose）
```

## 6. 验收场景

### 场景 1：打开命令菜单并展示命令列表

**前置条件**：聊天输入框处于聚焦状态，后端服务正常运行

**步骤**：

1. 用户在输入框中键入 `/`
2. 等待命令菜单出现

**预期结果**：

- 命令菜单在输入框上方弹出
- 展示来自后端的命令和前端内置命令（`new`、`compact`）
- 每个命令显示名称和描述
- 第一项处于高亮状态
- 底部显示键盘操作提示（桌面端）

### 场景 2：过滤命令列表

**前置条件**：命令菜单已打开，命令列表已加载

**步骤**：

1. 用户继续输入 `comp`
2. 观察命令列表变化

**预期结果**：

- 仅展示名称或描述包含 "comp" 的命令（如 `/compact`）
- 不包含 "comp" 的命令被隐藏
- 选中索引重置为第一项
- 若无匹配命令，显示"无匹配命令"提示

### 场景 3：键盘导航选择命令

**前置条件**：命令菜单已打开，有多个命令可见

**步骤**：

1. 按 `↓` 箭头键两次
2. 按 `Enter` 键

**预期结果**：

- 步骤 1 后，高亮项下移两格
- 步骤 2 后，当前高亮命令被传递给 `onSelect` 回调
- 菜单关闭

### 场景 4：点击外部关闭菜单

**前置条件**：命令菜单已打开

**步骤**：

1. 点击命令菜单外部区域

**预期结果**：

- `onClose` 回调被调用
- 命令菜单消失

### 场景 5：后端不可达时的降级

**前置条件**：命令菜单已打开，后端服务不可达

**步骤**：

1. 等待命令加载完成
2. 观察命令列表

**预期结果**：

- 仅展示前端内置命令（`new`、`compact`）
- 不显示错误阻断界面
- 用户仍可正常选择和执行前端命令

### 场景 6：空查询展示全部命令

**前置条件**：命令菜单已打开，命令列表已加载

**步骤**：

1. 确保查询文本为空（仅键入 `/` 后未输入其他字符）

**预期结果**：

- 展示全部可用命令
- 不执行任何过滤

### 场景 7：命令加载状态

**前置条件**：命令菜单刚打开，命令列表尚未加载完成

**步骤**：

1. 观察菜单内容

**预期结果**：

- 显示加载提示文本
- 不显示命令列表或空状态提示

### 场景 8：响应式高度适配

**前置条件**：命令菜单已打开，浏览器窗口高度较小

**步骤**：

1. 缩小浏览器窗口高度
2. 观察菜单高度变化

**预期结果**：

- 菜单最大高度自动缩减，防止被顶部元素遮挡
- 菜单内容可滚动
- 窗口恢复后高度计算正确

## 8. 架构决策记录

### ADR-001：为什么命令加载使用 requestAnimationFrame 而非直接执行

**决策**：命令列表加载和高度计算均通过 `requestAnimationFrame` 调度。

**理由**：

- 确保 DOM 布局完成后再执行计算，避免获取到错误的尺寸信息
- 与测试框架的假定时器兼容，便于单元测试
- 组件卸载时可正确取消，避免状态更新到已卸载组件

### ADR-002：为什么前端命令不覆盖后端同名命令

**决策**：当后端返回的命令与前端内置命令同名时，以后端命令为准。

**理由**：

- 后端命令代表服务器实际支持的功能
- 前端命令仅作为降级方案存在
- 避免前后端命令行为不一致导致的混淆

### ADR-003：为什么使用 forwardRef 暴露导航方法

**决策**：通过 `forwardRef` 和 `useImperativeHandle` 暴露 `moveUp`、`moveDown`、`selectCurrent`、`getSelectedCommand` 方法。

**理由**：

- 键盘事件由父组件（输入框）统一处理，子组件无法直接捕获
- 父组件需要在 `onKeyDown` 中调用导航方法
- 相比事件回调方式，句柄调用更直接，避免额外的状态同步

### ADR-004：为什么命令列宽度动态计算

**决策**：命令名称列宽度根据最长命令名动态计算，范围限制在 10ch 到 18ch。

**理由**：

- 固定宽度可能导致短命令浪费空间或长命令被截断
- 动态计算确保所有命令名称完整显示
- 上下限防止极端情况下的布局异常

## 9. 风险与缓解

| 风险                     | 影响                       | 缓解措施                                |
| ------------------------ | -------------------------- | --------------------------------------- |
| 后端命令加载缓慢         | 用户看到短暂空白或加载提示 | 请求防重入机制，避免重复请求            |
| 小屏幕下菜单被遮挡       | 用户无法看到完整命令列表   | 动态高度计算，基于可用空间自动调整      |
| 命令列表过长             | 菜单超出屏幕范围           | 最大高度限制 + 内部滚动                 |
| 快速连续输入导致过滤闪烁 | 用户体验不佳               | useMemo 缓存过滤结果，避免重复计算      |
| 移动端触摸操作与悬停冲突 | 选中状态异常               | 移动端隐藏操作提示，触摸直接触发选择    |
| 请求竞态（快速开关菜单） | 旧请求结果覆盖新状态       | requestIdRef 机制，仅处理最新请求的结果 |
