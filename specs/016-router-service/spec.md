# 动态端口路由服务

> 模块编号：016-router-service
> 状态：已实现
> 最后更新：2026-04-12

---

## 1. 模块概述

### 1.1 目的

动态端口路由服务运行在 Docker 容器内部，负责自动发现容器中正在运行的开发服务，并为每个服务生成可访问的预览链接。它解决了容器化开发环境中"服务跑在哪个端口.怎么从外部访问"的核心痛点。

### 1.2 解决的问题

- **端口发现**：容器内开发服务（前端 dev server.文档站点.API mock 等）监听端口不固定.需要自动扫描
- **访问代理**：容器内端口无法直接从外部访问.需要生成带令牌的路由并代理转发
- **生命周期同步**：服务启动后自动注册路由.服务停止后自动清理.无需手动配置
- **集中管理**：通过 Web 管理面板一览所有活跃路由.支持搜索.复制 URL.设置预览端口

### 1.3 范围

本模块涵盖：

- 定期扫描目标容器内指定端口范围的活跃监听端口
- 为每个新发现的端口生成唯一令牌并创建路由
- 将路由配置写入网关.并触发网关热重载
- 提供 Web 管理面板.展示所有活跃路由及其预览链接
- 支持设置一个"预览端口".将网关的预览入口指向该端口
- 路由状态持久化.服务重启后自动恢复

本模块不涵盖：

- 网关本身的部署与配置（由网关模块负责）
- 前端 UI 的主应用（由前端模块负责）
- 容器编排与生命周期管理

## 3. 功能需求

### FR-01：端口扫描

**描述**：定期扫描目标容器内指定端口范围的活跃监听端口。

**要求**：

- 通过读取容器内 `/proc/net/tcp` 和 `/proc/net/tcp6` 获取所有处于监听状态的端口
- 仅保留处于 `LISTEN` 状态（状态码 `0A`）的端口
- 扫描范围由配置决定.默认 `3000-9999`
- 排除配置中指定的端口.默认排除 `4096`
- 扫描间隔可配置.默认 5 秒
- 扫描失败时记录警告日志.不中断后续扫描周期

**验收标准**：

- 给定容器内端口 3000 和 5173 正在监听.扫描结果包含这两个端口
- 给定端口 4096 正在监听.扫描结果不包含该端口（已被排除）
- 给定端口 22 正在监听.扫描结果不包含该端口（不在扫描范围内）
- 给定扫描命令执行失败.日志记录警告.下一周期继续尝试

### FR-02：路由生成

**描述**：为新发现的端口自动生成唯一令牌并创建路由。

**要求**：

- 每个新端口分配一个随机令牌.默认长度 12 个字符（字母数字混合）
- 令牌必须全局唯一.生成后检查冲突.冲突则重新生成
- 路由记录包含端口号和创建时间戳（Unix 秒级）
- 路由创建后.立即写入网关配置并触发网关热重载
- 路由创建后.持久化到状态文件

**验收标准**：

- 给定新端口 3000 被发现.生成令牌并创建路由 `/p/{token}/`
- 给定同一端口被多次扫描.不重复创建路由
- 给定令牌冲突.重新生成直到唯一

### FR-03：管理面板

**描述**：提供 Web UI 管理面板.展示所有活跃路由。

**要求**：

- 管理面板通过 `/routes` 路径访问
- 默认返回 HTML 页面.支持 `?format=json` 返回 JSON 数据
- 页面展示每条路由的端口号.令牌.创建时间（相对时间）.完整预览 URL
- 支持按端口号.令牌或 URL 进行前端搜索过滤
- 支持一键复制单条 URL 和全部 URL
- 支持设置和取消预览端口
- 页面每 8 秒自动刷新数据
- 支持明暗主题切换（跟随系统.手动切换.自动三种模式）
- 管理面板接口受 Basic Auth 保护（当配置了密码时）

**验收标准**：

- 访问 `/routes` 返回包含所有路由的 HTML 页面
- 访问 `/routes?format=json` 返回 JSON 格式的路由列表
- 未配置密码时.管理面板无需认证即可访问
- 配置密码后.未携带正确认证信息的请求返回 401

### FR-04：代理转发

**描述**：网关根据路由配置.将预览请求转发到对应的容器内端口。

**要求**：

- 预览 URL 格式为 `/p/{token}/`.路径前缀在转发时被剥离
- 网关配置由路由服务动态生成.格式为网关可识别的配置语法
- 每次路由变更后.自动触发网关热重载
- 预览端口通过独立入口（端口 6659）访问.指向当前设置的预览端口

**验收标准**：

- 给定令牌 `abc123` 对应端口 3000.访问 `/p/abc123/` 转发到容器内 `:3000`
- 路径 `/p/abc123/assets/style.css` 转发到容器内 `/assets/style.css`
- 设置预览端口为 3000 后.预览入口流量转发到容器内 `:3000`

### FR-05：可配置扫描

**描述**：扫描行为通过环境变量进行配置。

**要求**：

| 环境变量               | 默认值              | 说明                                         |
| ---------------------- | ------------------- | -------------------------------------------- |
| `ROUTER_SCAN_INTERVAL` | `5`                 | 扫描间隔（秒）                               |
| `ROUTER_PORT_RANGE`    | `3000-9999`         | 扫描端口范围.格式 `起始-结束`                |
| `ROUTER_EXCLUDE_PORTS` | `4096`              | 排除的端口列表.逗号分隔                      |
| `ROUTER_TOKEN_LENGTH`  | `12`                | 令牌长度（字符数）                           |
| `TARGET_CONTAINER`     | `opencode-backend`  | 目标容器名称                                 |
| `ROUTER_STATE_FILE`    | `/data/routes.json` | 路由状态持久化文件路径                       |
| `PUBLIC_BASE_URL`      | 空                  | 公网基础 URL.用于生成完整预览链接            |
| `PREVIEW_DOMAIN`       | 空                  | 预览专用域名.优先级高于 PUBLIC_BASE_URL      |
| `ROUTER_USERNAME`      | 空                  | 管理面板 Basic Auth 用户名                   |
| `ROUTER_PASSWORD`      | 空                  | 管理面板 Basic Auth 密码（为空时不启用认证） |

**验收标准**：

- 给定 `ROUTER_SCAN_INTERVAL=10`.扫描间隔为 10 秒
- 给定 `ROUTER_PORT_RANGE=8000-9000`.仅扫描该范围
- 给定 `ROUTER_EXCLUDE_PORTS=4096,8080,9090`.这三个端口被排除
- 给定 `ROUTER_PORT_RANGE=9999-3000`.自动纠正为 `3000-9999`

### FR-06：令牌化 URL

**描述**：预览访问使用 `/p/{token}/` 格式的 URL。

**要求**：

- 令牌由大小写字母和数字组成.长度可配置
- URL 生成优先级：`PREVIEW_DOMAIN` > `PUBLIC_BASE_URL` > 当前请求来源
- 当 `PREVIEW_DOMAIN` 配置时.生成 `https://{domain}/p/{token}/`
- 当 `PUBLIC_BASE_URL` 配置时.生成 `{base_url}/p/{token}/`
- 两者均未配置时.使用当前请求的 origin 生成 URL

**验收标准**：

- 给定 `PREVIEW_DOMAIN=preview.example.com`.生成 `https://preview.example.com/p/{token}/`
- 给定 `PUBLIC_BASE_URL=https://app.example.com`.生成 `https://app.example.com/p/{token}/`
- 两者均未配置时.生成相对于当前请求的 URL

### FR-07：自动清理

**描述**：当容器内服务停止时.自动移除对应的路由。

**要求**：

- 每次扫描后.对比当前活跃端口与已有路由的端口
- 端口不再活跃的路由标记为过期并从路由表中移除
- 移除后更新网关配置并触发热重载
- 移除后更新持久化状态文件

**验收标准**：

- 给定端口 3000 的路由存在.但该端口已不再监听.路由被移除
- 给定端口 3000 的路由被移除.网关配置中对应的路由规则被删除
- 路由移除后.访问原令牌 URL 返回 404

### FR-08：数据持久化

**描述**：路由状态持久化到文件.服务重启后自动恢复。

**要求**：

- 路由状态以 JSON 格式写入文件.键为令牌.值为端口和创建时间
- 特殊键 `__preview_port__` 存储当前预览端口
- 服务启动时从文件加载状态.恢复路由表和预览端口
- 状态变更后立即写入文件
- 文件父目录不存在时自动创建

**验收标准**：

- 给定服务重启.重启后路由表与重启前一致
- 给定状态文件不存在.服务正常启动.路由表为空
- 给定状态文件格式错误.服务正常启动.路由表为空

## 4. 关键实体

### 4.1 路由（Route）

| 属性      | 类型   | 说明                        |
| --------- | ------ | --------------------------- |
| token     | string | 唯一令牌.用于 URL 路径      |
| port      | number | 容器内服务端口号            |
| publicUrl | string | 完整预览 URL                |
| createdAt | number | 创建时间（Unix 秒级时间戳） |

**行为**：

- 端口首次被发现时创建
- 端口不再监听时删除
- 令牌全局唯一.不可修改

### 4.2 路由状态文件

JSON 格式.存储所有路由和预览端口：

```json
{
  "abc123def456": { "port": 3000, "created_at": 1712900000 },
  "xyz789ghi012": { "port": 5173, "created_at": 1712900100 },
  "__preview_port__": 3000
}
```

**行为**：

- 以 `__` 开头的键为系统保留键.不作为路由处理
- 写入时按键排序.保证文件内容稳定
- 读取时解析失败返回空状态.不抛出异常

### 4.3 网关配置

路由服务动态生成的网关配置文件.包含两部分：

**路由配置**（`/etc/caddy/routes.conf`）：

- 每个路由生成一条匹配规则
- 匹配路径 `/p/{token}` 和 `/p/{token}/*`
- 转发时剥离 `/p/{token}` 前缀
- 反向代理到目标容器的对应端口

**预览配置**（`/etc/caddy/preview.conf`）：

- 设置预览端口时.生成反向代理规则指向该端口
- 未设置预览端口时.返回 503 并提示用户设置

**行为**：

- 路由变更后重新生成配置文件
- 生成后执行网关热重载命令

## 5. 架构

### 5.1 整体架构

```
┌─────────────┐     定期扫描      ┌──────────────────┐
│  目标容器    │ ◄─────────────── │   端口扫描器      │
│  (开发服务)   │ ──────────────► │  (读取 /proc/net) │
└─────────────┘                   └────────┬─────────┘
                                           │ 发现端口变化
                                           ▼
                                  ┌──────────────────┐
                                  │    路由表         │
                                  │  (内存 + 持久化)   │
                                  └────────┬─────────┘
                                           │ 路由变更
                              ┌────────────┼────────────┐
                              ▼            ▼            ▼
                       ┌──────────┐ ┌──────────┐ ┌──────────┐
                       │路由配置写入│ │预览配置写入│ │网关热重载 │
                       └──────────┘ └──────────┘ └──────────┘
```

### 5.2 数据流

1. **扫描周期触发**：定时器按配置间隔触发扫描
2. **端口发现**：读取目标容器 `/proc/net/tcp` 和 `/proc/net/tcp6`.解析监听端口
3. **差异对比**：将发现的端口与现有路由对比.识别新增和过期
4. **路由创建/删除**：新增端口生成令牌.过期端口移除路由
5. **配置更新**：重新生成网关路由配置和预览配置
6. **网关重载**：执行网关热重载命令使配置生效
7. **状态持久化**：将最新路由表写入状态文件

### 5.3 HTTP 端点

| 方法 | 路径                  | 说明                     | 认证       |
| ---- | --------------------- | ------------------------ | ---------- |
| GET  | `/routes`             | 管理面板（HTML 或 JSON） | Basic Auth |
| GET  | `/routes?format=json` | 路由列表 JSON 数据       | Basic Auth |
| POST | `/preview/set`        | 设置预览端口             | Basic Auth |
| GET  | `/preview/status`     | 查询预览端口状态         | Basic Auth |

### 5.4 服务监听

| 组件     | 端口 | 说明                      |
| -------- | ---- | ------------------------- |
| 路由服务 | 7070 | 内部管理端口.Gateway 代理 |
| Gateway  | 6658 | 统一入口.代理所有请求     |
| Gateway  | 6659 | 预览专用入口              |

### 5.5 Gateway 路由规则

端口 6658 上的请求按以下规则转发：

| 路径         | 转发目标       | 说明             |
| ------------ | -------------- | ---------------- |
| `/routes`    | Router :7070   | 动态路由管理面板 |
| `/preview/*` | Router :7070   | 预览端口设置 API |
| 其他         | Frontend :3000 | 前端静态资源     |

端口 6659 用于访问容器内开发服务.路由服务自动扫描 `3000-9999` 端口.通过 `/p/{token}/` 路径生成预览链接。

## 6. 验收场景

### 场景 1：服务启动后自动发现

**前置条件**：路由服务已启动.容器内无活跃开发服务

**步骤**：

1. 在容器内启动一个开发服务.监听端口 3000
2. 等待下一个扫描周期（默认 5 秒）
3. 访问 `/routes` 管理面板

**预期结果**：

- 管理面板显示一条新路由
- 路由包含端口号 3000.唯一令牌和完整预览 URL
- 网关配置已更新.包含该路由的转发规则
- 状态文件已写入.包含该路由信息

### 场景 2：服务停止后自动清理

**前置条件**：存在端口 3000 的活跃路由

**步骤**：

1. 停止容器内监听端口 3000 的服务
2. 等待下一个扫描周期
3. 访问 `/routes` 管理面板

**预期结果**：

- 管理面板中端口 3000 的路由已消失
- 网关配置中对应的转发规则已删除
- 状态文件中对应的令牌已移除
- 访问原预览 URL 返回 404

### 场景 3：服务重启后状态恢复

**前置条件**：存在多条活跃路由.状态文件已写入

**步骤**：

1. 重启路由服务
2. 等待服务启动完成
3. 访问 `/routes` 管理面板

**预期结果**：

- 管理面板显示重启前的所有路由
- 每条路由的令牌和端口与重启前一致
- 预览端口设置已恢复
- 网关配置已正确加载

### 场景 4：设置预览端口

**前置条件**：存在端口 3000 和 5173 的路由

**步骤**：

1. 通过管理面板设置预览端口为 3000
2. 通过预览入口（端口 6659）访问
3. 将预览端口切换为 5173
4. 再次通过预览入口访问

**预期结果**：

- 步骤 2 的流量转发到容器内 `:3000`
- 步骤 4 的流量转发到容器内 `:5173`
- 管理面板显示当前预览端口状态
- 预览端口设置已持久化

### 场景 5：管理面板认证

**前置条件**：配置了 `ROUTER_USERNAME` 和 `ROUTER_PASSWORD`

**步骤**：

1. 不带认证信息访问 `/routes`
2. 携带正确的 Basic Auth 认证信息访问 `/routes`
3. 携带错误的认证信息访问 `/routes`

**预期结果**：

- 步骤 1 返回 401 Unauthorized
- 步骤 2 正常返回管理面板
- 步骤 3 返回 401 Unauthorized

### 场景 6：配置自定义扫描范围

**前置条件**：配置 `ROUTER_PORT_RANGE=8000-8100`.`ROUTER_EXCLUDE_PORTS=8080,8443`

**步骤**：

1. 容器内端口 8000.8080.8100.3000 均在监听
2. 等待扫描周期完成
3. 检查管理面板中的路由

**预期结果**：

- 仅端口 8000 和 8100 被发现并创建路由
- 端口 8080 被排除（在排除列表中）
- 端口 3000 被排除（不在扫描范围内）

### 场景 7：JSON 格式输出

**前置条件**：存在多条活跃路由

**步骤**：

1. 访问 `/routes?format=json`

**预期结果**：

- 返回 JSON 格式数据
- 包含 routes 数组.每条路由有 token.port.publicUrl.createdAt 字段
- 包含 previewPort 和 previewDomain 字段
- 响应头包含 no-cache 缓存控制

## 8. 架构决策记录

### ADR-001：为什么通过 `/proc/net/tcp` 扫描端口

**决策**：通过 `docker exec` 读取容器内 `/proc/net/tcp` 和 `/proc/net/tcp6` 文件来发现监听端口。

**理由**：

- 无需在容器内安装额外工具（如 `netstat` 或 `ss`）
- `/proc/net/tcp` 是 Linux 内核接口.所有容器均可访问
- 解析简单.仅需读取文本并过滤状态码 `0A`（LISTEN）
- 性能开销极低.每次扫描仅执行一次 `cat` 命令

### ADR-002：为什么使用令牌而非端口号作为 URL 路径

**决策**：预览 URL 使用 `/p/{token}/` 格式.而非直接暴露端口号。

**理由**：

- 令牌不可预测.提供基本的安全隔离
- 端口号可能变化.令牌保持稳定
- 令牌长度固定.URL 格式统一
- 避免通过 URL 暴露容器内部结构

### ADR-003：为什么路由配置与预览配置分离

**决策**：路由配置（`routes.conf`）和预览配置（`preview.conf`）分别生成.由网关主配置文件 include。

**理由**：

- 路由配置频繁变更（每次扫描可能更新）.预览配置相对稳定
- 分离后网关主配置无需修改.只需 include 两个子文件
- 预览配置在未设置端口时可返回友好的 503 提示
- 降低配置冲突风险

### ADR-004：为什么状态文件使用 JSON 而非数据库

**决策**：路由状态以 JSON 文件形式持久化.而非使用 SQLite 或其他数据库。

**理由**：

- 数据量极小（通常几十条路由以内）.文件存储足够
- JSON 格式人类可读.便于调试和手动修复
- 无额外依赖.减少容器镜像体积
- 读写操作简单.无需事务和并发控制

## 9. 风险与缓解

| 风险             | 影响                        | 缓解措施                               |
| ---------------- | --------------------------- | -------------------------------------- |
| 扫描命令执行失败 | 路由无法更新.过期路由残留   | 失败时记录警告.下一周期重试.不中断服务 |
| 网关热重载失败   | 新路由不生效.旧路由仍可达   | 记录警告日志.配置已写入.下次重载时生效 |
| 状态文件损坏     | 服务重启后路由丢失          | 解析失败时返回空状态.从下次扫描重建    |
| 令牌碰撞         | 两个端口映射到同一路由      | 生成后检查冲突.冲突则重新生成          |
| 大量端口同时监听 | 路由表膨胀.管理面板加载缓慢 | 端口范围可配置.排除不需要的端口        |
| 容器名称变更     | 扫描目标不可达              | 通过环境变量配置.支持自定义容器名称    |
