## 1. Technical Context

### 1.1 模块定位

动态端口路由服务是 OpenCodeUI Docker 部署架构中的核心组件之一，运行在 Gateway 容器内部。它负责自动发现目标容器（默认 `opencode-backend`）中正在运行的开发服务，为每个服务生成带令牌的可访问预览链接，并通过动态更新 Caddy 网关配置实现流量转发。

### 1.2 技术栈

| 依赖                   | 版本       | 用途                                                 |
| ---------------------- | ---------- | ---------------------------------------------------- |
| `axum`                 | 0.8.8      | HTTP 服务框架，提供路由、中间件、响应处理            |
| `tokio`                | 1.50.0     | 异步运行时，提供事件循环、定时器、进程执行、文件系统 |
| `serde` + `serde_json` | 1.0.x      | JSON 序列化/反序列化，状态持久化                     |
| `rand`                 | 0.9.2      | 随机令牌生成（Alphanumeric 字符集）                  |
| `base64`               | 0.22.1     | Basic Auth 认证头解码                                |
| `log` + `env_logger`   | 0.4 / 0.11 | 日志输出，release 模式自动降级为 info 级别           |

## 3. Research Findings

### 3.1 端口扫描机制

扫描通过 `docker exec` 在目标容器内执行 `cat /proc/net/tcp /proc/net/tcp6` 实现。解析逻辑在 `scanner.rs` 的 `parse_proc_net_tcp()` 函数中：

- 跳过表头行（以 `sl` 开头）
- 提取第 2 列（local address）的端口部分（十六进制）
- 仅保留状态码为 `0A`（LISTEN）的条目
- 使用 `HashSet<u16>` 去重（tcp 和 tcp6 可能报告同一端口）
- 最终按配置的端口范围过滤，排除指定端口，排序后返回

扫描失败时记录 `log::warn!` 并返回 `Ok(())`，不中断后续扫描周期。

### 3.2 路由同步逻辑

`sync_routes()` 是核心同步函数，执行流程：

1. 获取当前活跃端口列表
2. 从内存 `state_map` 中提取已有路由
3. **新增路由**：遍历活跃端口，对不存在于路由表中的端口生成令牌
4. **清理路由**：遍历已有路由，移除端口不再活跃的条目
5. **变更检测**：仅在有新增或删除时才写入配置、持久化状态、触发热重载

令牌生成使用 `rand::distr::Alphanumeric`，生成后检查 `state_map` 中是否已存在，冲突则重新生成。

### 3.3 状态管理架构

采用双层状态管理：

- **内存层**：`Arc<RwLock<Map<String, Value>>>` 作为主数据源，所有读写操作通过此锁
- **磁盘层**：JSON 文件仅用于持久化，启动时加载到内存，变更后写回磁盘

`preview_port` 单独维护为 `Arc<RwLock<Option<u16>>>`，同时也在 `state_map` 中以 `__preview_port__` 键存储。

### 3.4 Caddy 配置生成

路由配置（`/etc/caddy/routes.conf`）格式：

```caddyfile
# Dynamic routes (auto generated by router)
@route_abc123 path /p/abc123 /p/abc123/*
handle @route_abc123 {
    uri strip_prefix /p/abc123
    reverse_proxy opencode-backend:3000
}
```

预览配置（`/etc/caddy/preview.conf`）：

- 设置端口时：`reverse_proxy opencode-backend:{port}`
- 未设置时：`respond "No preview port configured..." 503`

热重载通过执行 `caddy reload --config /etc/caddy/Caddyfile` 实现。

### 3.5 管理面板

管理面板是一个纯前端单页应用，通过 `include_str!("router.html")` 编译时嵌入二进制。关键特性：

- **SSR 数据注入**：服务端将路由数据序列化为 JSON，替换模板中的 `__INITIAL_DATA__` 占位符
- **自动刷新**：`setInterval(load, 8000)` 每 8 秒拉取最新数据
- **前端搜索**：按端口号、令牌或 URL 进行客户端过滤
- **主题切换**：localStorage 持久化主题偏好，支持 light/dark/auto 三种模式循环切换
- **预览端口管理**：点击眼睛图标设置/取消预览端口，调用 `POST /preview/set`
- **URL 复制**：支持单条复制和全部复制，使用 `navigator.clipboard.writeText`
- **响应式设计**：`max-width: 640px` 居中布局，移动端断点 480px

## 4. Data Model

### 4.1 核心实体

**RouteInfo**（`state.rs`）：

```rust
pub(crate) struct RouteInfo {
    pub(crate) port: u16,        // 容器内服务端口
    pub(crate) created_at: u64,  // Unix 秒级时间戳
}
```

**Config**（`config.rs`）：

```rust
pub struct Config {
    target_container: String,       // 目标容器名，默认 "opencode-backend"
    router_state_file: String,      // 状态文件路径，默认 "/data/routes.json"
    public_base_url: String,        // 公网基础 URL
    preview_domain: String,         // 预览专用域名
    router_username: String,        // Basic Auth 用户名
    router_password: String,        // Basic Auth 密码（空则不启用）
    scan_interval: u64,             // 扫描间隔（秒），默认 5
    token_length: usize,            // 令牌长度，默认 12
    port_range: (u16, u16),         // 扫描范围，默认 (3000, 9999)
    exclude_ports: HashSet<u16>,    // 排除端口，默认 {4096}
}
```

**AppState**（`router.rs`）：

```rust
pub struct AppState {
    config: Arc<Config>,
    state_map: Arc<RwLock<Map<String, Value>>>,  // 内存状态缓存
    preview_port: Arc<RwLock<Option<u16>>>,      // 当前预览端口
}
```

### 4.2 状态文件格式

JSON 文件，键为令牌字符串，值为路由信息对象：

```json
{
  "abc123def456": { "port": 3000, "created_at": 1712900000 },
  "xyz789ghi012": { "port": 5173, "created_at": 1712900100 },
  "__preview_port__": 3000
}
```

- 以 `__` 开头的键为系统保留键，`extract_routes()` 会过滤掉
- 写入时使用 `BTreeMap` 保证键排序
- 解析失败时返回空 `Map`，不抛出异常

### 4.3 HTTP 端点

| 方法 | 路径              | 处理函数             | 认证       | 说明                         |
| ---- | ----------------- | -------------------- | ---------- | ---------------------------- |
| GET  | `/routes`         | `get_routes`         | Basic Auth | 管理面板（HTML）或 JSON 数据 |
| POST | `/preview/set`    | `post_preview_set`   | Basic Auth | 设置预览端口                 |
| GET  | `/preview/status` | `get_preview_status` | Basic Auth | 查询预览端口状态             |

### 4.4 响应数据结构

**GET /routes?format=json**：

```json
{
  "routes": [{ "token": "abc123", "port": 3000, "publicUrl": "https://...", "createdAt": 1712900000 }],
  "previewPort": 3000,
  "previewDomain": "preview.example.com"
}
```

**POST /preview/set** 请求体：

```json
{ "port": 3000 }
```

**POST /preview/set** 成功响应：

```json
{ "ok": true, "previewPort": 3000 }
```

**GET /preview/status** 响应：

```json
{ "previewPort": 3000, "previewDomain": "preview.example.com" }
```

## 5. Interface Contracts

### 5.1 模块间接口

**scanner → config**：

- `list_listening_ports(&Config)` 读取 `target_container()`、`port_range()`、`exclude_ports()`

**router → scanner**：

- `sync_routes()` 调用 `scanner::list_listening_ports()` 获取活跃端口

**router → caddy**：

- `caddy::write_map(&Config, &BTreeMap<String, RouteInfo>)` 写入路由配置
- `caddy::write_preview_conf(&Config, Option<u16>)` 写入预览配置
- `caddy::reload_gateway()` 执行热重载

**router → state**：

- `state::load_state_map(&str)` 启动时加载
- `state::save_state_map(&str, &Map)` 变更后持久化
- `state::extract_routes(&Map)` 从状态 Map 中提取路由
- `state::route_to_value(&RouteInfo)` 序列化路由为 JSON Value
- `state::load_preview_port(&Map)` 加载预览端口
- `state::set_preview_port_value(&mut Map, Option<u16>)` 设置预览端口

**router → config**：

- 读取所有配置项：`scan_interval()`、`token_length()`、`public_base_url()`、`preview_domain()`、`router_username()`、`router_password()`

### 5.2 外部接口

**Docker**：

- 通过 `docker exec {container} sh -c "cat /proc/net/tcp /proc/net/tcp6"` 读取端口状态
- 要求 Router 进程有权限执行 Docker 命令

**Caddy Gateway**：

- 写入 `/etc/caddy/routes.conf` 和 `/etc/caddy/preview.conf`
- 执行 `caddy reload --config /etc/caddy/Caddyfile` 触发热重载
- 要求 Router 进程有权限写入这些路径并执行 Caddy 命令

**状态文件卷**：

- 默认路径 `/data/routes.json`
- 通过 `opencode-router-data` Docker 卷持久化

## 6. Implementation Strategy

### 6.1 启动流程

```
main()
  ├─ env_logger::init()
  ├─ Config::from_env()          ← 解析环境变量，应用默认值
  ├─ AppState::new(config)       ← 初始化空状态
  ├─ state.initialize()          ← 从磁盘加载状态，恢复路由和预览端口
  │   ├─ state::load_state_map()
  │   ├─ state::load_preview_port()
  │   └─ caddy::write_preview_conf()  ← 恢复预览配置
  ├─ state.spawn_sync_loop()     ← 启动后台扫描协程
  │   └─ tokio::spawn(async { loop { ticker.tick(); sync_routes(); } })
  ├─ router::app(state)          ← 构建 Axum 路由树
  ├─ TcpListener::bind([0.0.0.0]:7070)
  └─ axum::serve(listener, app).with_graceful_shutdown(ctrl_c)
```

### 6.2 扫描周期

```
sync_routes()
  ├─ scanner::list_listening_ports()     ← 获取活跃端口
  ├─ 对比现有路由，识别新增和过期
  ├─ 新增：生成令牌 → 插入 state_map
  ├─ 过期：从 state_map 移除
  ├─ 如有变更：
  │   ├─ caddy::write_map()              ← 写入 routes.conf
  │   ├─ state::save_state_map()         ← 持久化到磁盘
  │   └─ reload_gateway()                ← 触发热重载
  └─ 如无变更：跳过写入（减少 I/O）
```

### 6.3 URL 生成优先级

`public_url()` 方法的优先级：

1. `PREVIEW_DOMAIN` 非空 → `https://{domain}/p/{token}/`
2. `PUBLIC_BASE_URL` 非空 → `{base_url}/p/{token}/`
3. 两者均空 → 返回空字符串（前端回退到 `location.origin`）

### 6.4 Basic Auth 实现

`check_basic_auth()` 流程：

1. 若 `router_password` 为空，直接放行（不启用认证）
2. 提取 `Authorization` 头，验证 `Basic ` 前缀
3. Base64 解码，解析 `username:password` 格式
4. 与配置的 `router_username` 和 `router_password` 逐字比对

未通过认证时返回 401 + `WWW-Authenticate: Basic` 头。

### 6.5 优雅关闭

通过 `tokio::signal::ctrl_c()` 监听 SIGINT/SIGTERM，触发 Axum 的 `with_graceful_shutdown()` 机制，等待正在处理的请求完成后退出。

## 7. Error Handling

### 7.1 错误处理策略

| 场景               | 处理方式                           | 影响                                     |
| ------------------ | ---------------------------------- | ---------------------------------------- |
| 端口扫描命令失败   | `log::warn!` + 返回 `Ok(())`       | 本次扫描跳过，下一周期重试               |
| Caddy 配置写入失败 | 向上传播错误，记录 `log::error!`   | 路由表已更新但配置未写入，下次变更时重试 |
| Caddy 热重载失败   | `log::warn!` + 继续                | 配置已写入但未生效，下次重载时生效       |
| 状态文件读取失败   | 返回空 `Map`                       | 从空状态开始，下次扫描重建路由           |
| 状态文件写入失败   | 向上传播错误                       | 内存状态已更新，磁盘未同步，重启后丢失   |
| 状态文件解析失败   | `unwrap_or_default()` 返回空 `Map` | 同读取失败                               |
| 令牌碰撞           | while 循环重新生成                 | 极低概率（12 位字母数字，62^12 种组合）  |
| 端口范围颠倒       | `std::mem::swap` 自动纠正          | `9999-3000` 纠正为 `3000-9999`           |
| 无效 JSON 请求体   | 返回 400 Bad Request               | 客户端错误，不影响服务                   |

### 7.2 日志级别

| 级别     | 使用场景                                                 |
| -------- | -------------------------------------------------------- |
| `info!`  | 服务启动、新路由创建、路由移除、路由表更新、预览端口设置 |
| `warn!`  | 扫描命令失败、Caddy 热重载失败                           |
| `error!` | 同步循环异常、Caddy 配置写入失败、设置预览端口失败       |

Release 模式下 `log` crate 的 `release_max_level_info` 特性自动过滤 `debug!` 和 `trace!`。

## 9. 已知差异与改进空间

### 9.1 spec.md 与实现的差异

| 需求                             | spec 描述           | 实际实现                                     | 差异评估               |

### 9.2 潜在改进

1. **扫描命令优化**：当前每次扫描都执行 `docker exec`，可考虑在容器内直接读取 `/proc/net/tcp`（如果 Router 与目标容器共享 PID namespace）
2. **状态文件原子写入**：当前 `fs::write()` 非原子操作，写入中断可能导致文件损坏。可改用写入临时文件后 rename 的方式
3. **Caddy API 替代**：当前通过文件写入 + reload 更新配置，可考虑使用 Caddy Admin API 实现零停机更新
4. **健康检查端点**：缺少 `/health` 端点，不利于容器编排的健康探测
5. **指标暴露**：可添加 Prometheus 格式的 `/metrics` 端点，暴露扫描延迟、路由数量等指标
