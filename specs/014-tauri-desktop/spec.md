> 模块编号：014-tauri-desktop

## 1. 模块概述

### 1.1 目的

将 OpenCodeUI 的 Web 前端打包为原生桌面应用程序，使用户能够以独立客户端的形式运行，获得原生窗口管理、本地后端集成、跨平台分发等桌面级体验。

### 1.2 解决的问题

- **原生桌面体验**：摆脱浏览器地址栏和标签页，提供沉浸式的全屏工作空间
- **CORS 绕过**：通过 Rust 侧 HTTP 客户端直接调用后端 API，无需处理浏览器跨域限制
- **SSE 桥接**：在 Rust 侧建立 SSE 长连接并转发至 Web 层，解决 WebView 中 SSE 连接的稳定性问题
- **本地后端管理**：桌面端可直接启动、停止、检测本地 OpenCode 服务，简化用户操作
- **跨平台分发**：一套代码同时构建 macOS、Linux、Windows 安装包
- **系统集成**：Windows 右键菜单、macOS 拖放打开、多窗口支持等原生能力

### 1.3 范围

本模块涵盖：

- Tauri 应用初始化与配置
- WebView 窗口管理与多窗口支持
- Rust 侧 SSE 客户端与事件桥接
- Rust 侧 HTTP 客户端（绕过 CORS）
- OpenCode 服务生命周期管理（启动、停止、健康检查）
- 安全能力声明与权限控制
- 跨平台构建与打包（NSIS / DMG / DEB）
- 平台特定集成（Windows 右键菜单、macOS 文件关联）
- 日志系统与调试支持
- 桌面通知能力

本模块不涵盖：

- Web 前端业务逻辑（由前端模块负责）
- OpenCode 后端本身的实现
- 移动端应用构建（Android / iOS 使用独立入口）

## 3. 功能需求

### FR-01：原生 Shell 封装

**描述**：将 Web 前端嵌入原生窗口，提供完整的桌面应用体验。

**要求**：

- 使用 WebView 加载前端构建产物
- 窗口默认尺寸 800x600，支持自由调整大小
- 禁用文件拖放至窗口的行为，避免意外触发
- 开发模式下自动加载 Vite 开发服务器地址
- 生产模式下加载本地构建的静态资源
- 构建前自动执行前端构建命令，开发前自动启动开发服务器

**验收标准**：

- 给定生产构建产物，应用启动后显示完整的前端界面
- 给定开发模式，应用启动后连接 Vite 开发服务器并支持热更新
- 窗口可以自由调整大小，内容正确适配

### FR-02：跨平台构建

**描述**：支持在 macOS、Linux、Windows 上构建和运行桌面应用。

**要求**：

- macOS 构建输出 DMG 安装包
- Linux 构建输出 DEB 安装包
- Windows 构建输出 NSIS 安装程序
- 各平台使用统一的图标资源集
- 构建产物包含应用名称、版本、作者等元信息

**验收标准**：

- 给定 macOS 环境，构建生成可安装的 DMG 文件
- 给定 Linux 环境，构建生成可安装的 DEB 文件
- 给定 Windows 环境，构建生成可安装的 NSIS 程序
- 安装包安装后应用名称和图标正确显示

### FR-03：原生 HTTP 客户端

**描述**：通过 Rust 侧 HTTP 客户端发起 API 请求，完全绕过 WebView 的 CORS 限制。

**要求**：

- 使用 Rust HTTP 库作为 API 请求的代理层
- 支持 HTTP 和 HTTPS 协议
- 支持自定义请求头（包括 Authorization）
- 连接超时 15 秒，TCP 保活 30 秒
- 前端通过 Tauri 命令调用 HTTP 能力

**验收标准**：

- 给定跨域后端地址，API 请求正常返回结果
- 给定需要认证的服务器，请求携带正确的 Authorization 头
- 给定网络不可达，请求在超时时间内返回错误

### FR-04：SSE 桥接

**描述**：在 Rust 侧建立 SSE 长连接，将事件通过 Tauri Channel 转发至 Web 前端。

**要求**：

- Rust 侧使用 HTTP 客户端建立 SSE 连接
- 使用 Tauri Channel 将事件流式推送给前端
- 支持三种事件类型：已连接、收到消息、断开连接、发生错误
- 每条消息以原始 JSON 字符串形式转发，由前端自行解析
- 连接超时 90 秒无数据则判定为连接死亡
- TCP 保活 30 秒，防止中间设备断开空闲连接
- 支持多窗口独立 SSE 连接，互不干扰
- 窗口销毁时自动清理对应 SSE 连接
- 前端可主动调用断开命令终止 SSE 连接

**验收标准**：

- 给定有效的 SSE 端点，Rust 侧成功建立连接并向前端发送 Connected 事件
- 给定服务端推送数据，前端通过 Channel 收到对应的 Message 事件
- 给定服务端断开连接，前端收到 Disconnected 事件
- 给定网络异常，前端收到 Error 事件
- 给定多窗口同时连接 SSE，各窗口事件互不串扰
- 给定窗口关闭，对应 SSE 连接自动清理

### FR-05：插件系统

**描述**：注册并使用 Tauri 插件扩展应用原生能力。

**要求**：

- HTTP 插件：提供原生 HTTP 请求能力
- 通知插件：支持桌面推送通知
- 对话框插件：支持文件选择、保存等对话框
- 文件系统插件：支持本地文件读写
- 打开器插件：支持在默认应用中打开文件或 URL
- 日志插件：记录应用运行日志
- 单实例插件：防止同一应用启动多个实例

**验收标准**：

- 所有插件在应用启动时正确注册
- 各插件功能可通过 Tauri API 正常调用
- 插件权限受安全能力声明约束

### FR-06：安全能力声明

**描述**：通过能力配置文件声明应用所需的权限范围。

**要求**：

- 声明核心默认权限
- HTTP 权限允许所有 http/https URL（含端口和路径）
- 通知权限包含检查权限、请求权限、发送通知
- 对话框权限包含打开和保存对话框
- 文件系统权限包含文件读写
- 打开器权限使用默认配置
- 能力作用于主窗口及所有动态创建的窗口

**验收标准**：

- 给定能力配置文件，应用启动时权限正确加载
- 给定未声明的权限操作，调用被拒绝
- 给定 HTTP 请求，URL 匹配允许的规则时请求成功

### FR-07：OpenCode 服务管理

**描述**：桌面端可直接管理本地 OpenCode 服务的生命周期。

**要求**：

- 检查服务是否运行：通过健康检查端点判断
- 启动服务：执行 `opencode serve` 命令，支持自定义二进制路径和环境变量
- 停止服务：通过进程 ID 终止子进程
- 健康检查轮询：启动后每 500ms 检查一次，最多 30 次
- 跟踪服务状态：记录是否由本应用启动、子进程 PID
- 跨平台进程终止：Windows 使用 taskkill，Unix 使用 kill
- Windows 启动子进程时隐藏控制台窗口

**验收标准**：

- 给定服务未运行，调用启动命令后服务在 15 秒内就绪
- 给定服务已在运行，调用启动命令返回 false
- 给定调用停止命令，对应进程被终止
- 给定 Windows 平台，启动子进程时不弹出控制台窗口

### FR-08：多窗口支持

**描述**：支持同时打开多个应用窗口，每个窗口独立工作。

**要求**：

- 主窗口标签为 `main`，动态窗口标签格式为 `win-{序号}`
- 使用原子计数器保证窗口标签唯一
- 每个窗口独立维护 SSE 连接状态
- 窗口销毁时自动清理关联资源
- 最后一个窗口关闭时，若服务由本应用启动，则询问是否停止服务

**验收标准**：

- 给定新建窗口操作，新窗口正确创建并加载内容
- 给定多个窗口同时运行，各窗口 SSE 连接互不干扰
- 给定关闭最后一个窗口，弹出确认对话框

### FR-09：目录关联打开

**描述**：支持通过多种方式将本地目录关联到应用窗口。

**要求**：

- **命令行参数**：启动时第一个非选项参数若为有效目录，则关联到主窗口
- **Windows 右键菜单**：安装时注册文件夹右键"Open with OpenCode"
- **macOS 文件关联**：支持 Finder 右键"用...打开"和拖放文件夹到 Dock 图标
- **单实例协议**：已运行时再次打开文件，新建窗口而非复用已有窗口
- 目录路径通过状态对象传递，前端启动后一次性读取并清空

**验收标准**：

- 给定命令行 `app /path/to/dir`，主窗口关联到指定目录
- 给定 Windows 右键文件夹选择"Open with OpenCode"，新窗口打开该目录
- 给定 macOS 拖放文件夹到 Dock 图标，新窗口打开该目录
- 给定应用已运行，再次打开目录时新建窗口而非切换已有窗口

### FR-10：日志与调试

**描述**：提供运行日志记录和开发调试支持。

**要求**：

- 日志级别默认设置为 Info
- 日志输出到文件和控制台
- 开发模式下自动打开 DevTools
- 关键操作（服务启停、SSE 连接、窗口创建）记录日志

**验收标准**：

- 给定应用运行，日志文件记录关键事件
- 给定开发模式，窗口自动打开开发者工具
- 给定 SSE 连接失败，日志中包含错误详情

### FR-11：桌面通知

**描述**：支持通过系统通知推送消息给用户。

**要求**：

- 前端通过 Tauri 通知 API 发送桌面通知
- 支持通知权限检查和请求
- 通知配置在 tauri.conf.json 中声明

**验收标准**：

- 给定前端调用通知 API，系统通知栏显示对应消息
- 给定未授权通知权限，先请求权限再发送

### FR-12：构建优化

**描述**：Release 构建产物经过优化，减小体积并提升性能。

**要求**：

- 启用符号剥离（strip）
- 启用链接时优化（LTO thin）
- 启用 panic abort 策略
- 代码生成单元设为 1

**验收标准**：

- 给定 release 构建，产物体积明显小于 debug 构建
- 应用启动和运行性能符合预期

## 4. 关键实体

### 4.1 SSE 连接状态

| 属性    | 类型      | 说明                     |
| ------- | --------- | ------------------------ |
| next_id | AtomicU64 | 递增连接 ID 计数器       |
| active  | HashMap   | 窗口标签到连接 ID 的映射 |

**行为**：

- 每次新连接分配唯一递增 ID
- 按窗口标签隔离连接状态
- 支持并发安全的读写操作

### 4.2 SSE 事件

| 事件类型     | 数据字段        | 说明                       |
| ------------ | --------------- | -------------------------- |
| Connected    | 无              | SSE 连接已建立             |
| Message      | raw: String     | 收到 SSE 数据（原始 JSON） |
| Disconnected | reason: String  | 连接正常断开               |
| Error        | message: String | 连接发生错误               |

### 4.3 服务状态

| 属性       | 类型       | 说明             |
| ---------- | ---------- | ---------------- |
| child_pid  | AtomicU32  | 子进程 PID       |
| we_started | AtomicBool | 是否由本应用启动 |

**行为**：

- 启动服务时记录 PID 和启动标记
- 停止服务时清除 PID 和标记
- 关闭应用时根据标记决定是否停止服务

### 4.4 目录状态

| 属性    | 类型    | 说明                     |
| ------- | ------- | ------------------------ |
| pending | HashMap | 窗口标签到目录路径的映射 |

**行为**：

- 启动时或打开文件时写入待处理目录
- 前端读取后自动清除（一次性消费）
- 支持多窗口各自独立关联目录

### 4.5 Tauri 命令

| 命令                      | 平台限制 | 说明                         |
| ------------------------- | -------- | ---------------------------- |
| sse_connect               | 全部     | 建立 SSE 连接                |
| sse_disconnect            | 全部     | 断开 SSE 连接                |
| get_cli_directory         | 桌面     | 获取启动时传入的目录路径     |
| check_opencode_service    | 桌面     | 检查 OpenCode 服务是否运行   |
| start_opencode_service    | 桌面     | 启动 OpenCode 服务           |
| stop_opencode_service     | 桌面     | 停止 OpenCode 服务           |
| get_service_started_by_us | 桌面     | 查询服务是否由本应用启动     |
| confirm_close_app         | 桌面     | 确认关闭应用（可选停止服务） |

## 5. 数据流

### 5.1 SSE 桥接流

```
前端调用 sse_connect(url, authHeader)
    ↓
Rust 侧创建 reqwest HTTP 客户端
    ↓
发起 GET 请求到 SSE 端点
    ↓
连接成功，通过 Channel 发送 Connected 事件
    ↓
流式读取 SSE 数据块
    ↓
解析 data: 行，累积完整消息
    ↓
通过 Channel 发送 Message 事件（原始 JSON）
    ↓
前端接收并解析 JSON，更新 UI
```

### 5.2 服务管理流

```
前端调用 start_opencode_service(url, binaryPath, envVars)
    ↓
检查服务是否已在运行（健康检查）
    ↓
若未运行，spawn opencode serve 子进程
    ↓
记录子进程 PID 和启动标记
    ↓
轮询健康检查（500ms 间隔，最多 30 次）
    ↓
服务就绪后返回 true
```

### 5.3 目录关联流

```
用户通过右键/拖放/命令行打开目录
    ↓
应用解析目录路径，写入 OpenDirectoryState.pending
    ↓
前端启动后调用 get_cli_directory
    ↓
读取并清除 pending 中的目录
    ↓
前端加载对应目录的工作区
```

### 5.4 窗口关闭流

```
用户点击窗口关闭按钮
    ↓
判断是否为最后一个窗口
    ↓
若是且服务由本应用启动
    ↓
发送 close-requested 事件给前端
    ↓
前端弹出确认对话框（是否停止服务）
    ↓
用户确认后调用 confirm_close_app
    ↓
可选停止服务，销毁窗口
```

### 7.2 通信机制

| 方向        | 机制          | 用途                           |
| ----------- | ------------- | ------------------------------ |
| 前端 → Rust | Tauri invoke  | 调用命令（SSE、服务管理等）    |
| Rust → 前端 | Tauri Channel | SSE 事件流式推送               |
| Rust → 前端 | Tauri emit    | 系统事件（close-requested 等） |
| 前端 → Rust | Tauri listen  | 监听系统事件                   |

### 7.3 多窗口架构

```
AppHandle
├── Window "main" ──► SSE Conn #1 ──► Channel → 前端
├── Window "win-1" ──► SSE Conn #2 ──► Channel → 前端
├── Window "win-2" ──► SSE Conn #3 ──► Channel → 前端
│
├── SseState (全局共享)
│   ├── next_id: AtomicU64
│   └── active: { "main" → 1, "win-1" → 2, "win-2" → 3 }
│
├── ServiceState (全局共享)
│   ├── child_pid: AtomicU32
│   └── we_started: AtomicBool
│
└── OpenDirectoryState (全局共享，桌面端)
    └── pending: { "main" → "/path/to/dir" }
```

## 9. 验收场景

### 场景 1：安装并启动桌面应用

**前置条件**：已下载对应平台的安装包

**步骤**：

1. 运行安装程序
2. 完成安装向导
3. 从应用程序菜单或桌面启动 OpenCode

**预期结果**：

- 安装过程无错误
- 应用图标和名称正确显示
- 窗口打开后显示完整的 OpenCodeUI 界面

### 场景 2：SSE 桥接正常工作

**前置条件**：应用已启动，后端服务运行中

**步骤**：

1. 在前端发起 SSE 连接
2. 等待连接建立
3. 观察后端推送的事件

**预期结果**：

- 前端收到 Connected 事件
- 后端推送的数据通过 Message 事件到达前端
- 数据格式为原始 JSON 字符串，前端可正常解析
- 连接保持活跃，不会无故断开

**前置条件**：本地已安装 OpenCode 二进制

**步骤**：

1. 在设置中配置 OpenCode 二进制路径
2. 点击启动服务按钮
3. 等待服务就绪
4. 点击停止服务按钮

**预期结果**：

- 服务在 15 秒内启动并通过健康检查
- 前端显示服务运行状态
- 停止服务后，进程被正确终止
- 再次启动时检测到服务未运行，正常启动

- 应用启动并打开新窗口

- 如果应用已在运行，不启动新实例而是新建窗口

**前置条件**：macOS 平台，应用已安装

## 11. 架构决策记录

### ADR-001：为什么 SSE 桥接放在 Rust 侧

**决策**：SSE 连接在 Rust 侧建立，通过 Tauri Channel 转发事件给前端。

**理由**：

- WebView 中的 SSE 连接受浏览器 CORS 策略限制
- WebView 中的长连接稳定性不如原生 HTTP 客户端
- Rust 侧可精确控制超时、保活、重连等行为
- Channel 机制提供类型安全的流式数据传输
- 前端只需处理 JSON 解析，不需要关心连接细节

### ADR-002：为什么服务管理仅限桌面端

**决策**：OpenCode 服务管理功能（启动、停止、健康检查）仅在桌面端可用，移动端不包含。

**理由**：

- 移动端不允许随意启动后台服务进程
- 移动端的进程管理与桌面端差异巨大
- 移动端通常连接远程后端，不需要本地服务
- 通过条件编译（`#[cfg(not(target_os = "android"))]`）实现平台隔离

### ADR-003：为什么单实例模式下打开目录新建窗口

**决策**：应用已运行时，再次打开目录（通过右键、拖放等）始终新建窗口，而非复用已有窗口。

**理由**：

- 参考 VSCode 等成熟编辑器的行为模式
- 用户双击不同文件夹的意图是分别查看，而非切换
- 多窗口支持允许并行工作
- 避免破坏用户已有窗口的状态

### ADR-004：为什么 SSE 消息以原始 JSON 字符串转发

**决策**：Rust 侧不解析 SSE 数据内容，直接以原始 JSON 字符串转发给前端。

**理由**：

- SSE 数据格式由后端定义，前端最了解其结构
- 避免 Rust 侧维护与后端一致的数据模型
- 减少 Rust 侧的序列化/反序列化开销
- 前端可根据需要灵活解析和过滤

### ADR-005：为什么使用 papaya 并发 HashMap

**决策**：SSE 状态和目录状态使用 papaya 库的并发 HashMap。

**理由**：

- 多窗口并发读写需要线程安全的数据结构
- papaya 提供无锁并发访问，性能优于 Mutex 包装
- 配合 rapidhash 提供高性能哈希
- 适合读多写少的场景（状态查询频繁，修改较少）

## 12. 风险与缓解

| 风险                          | 影响                               | 缓解措施                                          |
| ----------------------------- | ---------------------------------- | ------------------------------------------------- |
| SSE 连接静默断开              | 前端收不到事件，用户无感知         | 90 秒读取超时检测，超时后发送 Error 事件          |
| 子进程僵尸进程                | 应用关闭后 opencode serve 仍在运行 | 关闭时根据 we_started 标记决定是否终止子进程      |
| 多窗口 SSE 连接互相干扰       | 一个窗口断开影响其他窗口           | 按窗口标签隔离连接状态，使用独立连接 ID           |
| WebView 引擎差异              | 不同平台渲染或行为不一致           | 使用系统原生 WebView，测试覆盖三大平台            |
| Windows NSIS 安装脚本错误     | 右键菜单注册失败                   | 安装钩子使用 HKCU 而非 HKLM，避免权限问题         |
| UTF-8 多字节字符跨 chunk 截断 | SSE 数据解析出现乱码               | drain_sse_messages 使用字节缓冲，完整字符后再解析 |
| 前端构建产物缺失              | 生产模式启动白屏                   | beforeBuildCommand 确保构建先执行                 |
| 并发目录切换导致状态不一致    | 快速打开多个目录时窗口关联错误     | pending 状态按窗口标签隔离，一次性读取后清除      |
